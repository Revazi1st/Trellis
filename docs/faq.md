# FAQ

Short answers to the first questions, each with the page that has the long one.

## Can I use SQL Server, MongoDB or another database?

The solution uses PostgreSQL, and no option changes the engine. The AppHost pins the major version of
the PostgreSQL image (`tools/Trellis.AppHost/Program.cs`), and `docker-compose.yml` starts the same
major for the dev-container flow. Among the places that are specific to PostgreSQL are:

- the provider registration and the design-time factory, which call `UseNpgsql`
  (`src/Infrastructure/Trellis.Persistence/DependencyInjection.cs` and `AppDbContextFactory.cs`);
- the `xmin` system column as an aggregate's concurrency token, mapped in the aggregate's EF
  configuration (the sample's `Configurations/InvoiceConfiguration.cs` is the example);
- the outbox payload stored as `jsonb`, and the filtered index over the pending rows
  (`Outbox/OutboxMessageConfiguration.cs`);
- the outbox claim, a `FOR UPDATE SKIP LOCKED` query (`Outbox/OutboxProcessor.cs`);
- a unique violation, recognised by `PostgresException` and its SQLSTATE (`UniqueConstraintErrors.cs`);
- every `DateTimeOffset` written as UTC for a `timestamptz` column
  (`Conversions/UtcDateTimeOffsetConverter.cs`);
- the Npgsql settings of the API and of the migration worker (`EnrichNpgsqlDbContext` in each
  `Program.cs`);
- the shipped migration, generated by the Npgsql provider (`Migrations/`);
- the database the AppHost and `docker-compose.yml` start;
- the integration tests and the API tests, which start PostgreSQL in Testcontainers
  ([development.md](development.md#tests)).

Another relational engine starts with these places and a new set of migrations. The aggregates, their
outbox rows and the Identity tables share one EF Core context, `AppDbContext`, and a command's writes
commit in one transaction ([architecture.md](architecture.md#domain-events-and-integration-events)).

## Why is there no MediatR, AutoMapper or FluentAssertions?

Their recent versions moved to commercial or proprietary licenses, and the build refuses every
package on the license ceilings, transitive ones included: `LicenseCeilingPackageIds` in
`Directory.Build.props` lists them, and `Directory.Packages.props` gives each one's license and what
the solution uses instead. Handlers are plain classes that an endpoint injects, behind a decorator
pipeline; mapping is written by hand, and the tests assert with Shouldly
([ADR-0011](adr/0011-license-ceiling-policy.md), [ADR-0003](adr/0003-hand-rolled-cqrs.md)).

## How do I remove the sample feature, or add my own?

The [`add-feature`](../.claude/skills/add-feature/SKILL.md) skill copies the reference slice for a new
aggregate or use case, from the Domain outward. Once your own first feature exists, the
[`remove-feature`](../.claude/skills/remove-feature/SKILL.md) skill deletes the sample. The other ways
to make the solution yours are in [What you get](overview.md#make-it-yours).

## Can I turn an option on or off later?

Options are chosen when the solution is created, and the marker at the repository root,
.trellis\-template.json, records them. To change one, generate the solution again into a scratch
directory with the same name and the changed option, diff and merge; an option that changes the
schema, such as `--use-multitenancy`, also needs the migration step
([upgrading.md](upgrading.md), steps 3 to 5).

## Does a newer template version change my solution?

No. `dotnet new` takes a snapshot, and nothing updates the solution afterwards. Adopting a later
version is a regenerate, diff and merge, which the `upgrade-template` skill walks through with you
([upgrading.md](upgrading.md); [Versions and support](upgrading.md#versions-and-support) says which
versions get fixes).

## Why is the UI built with Blazor?

Blazor lets the UI be a reusable component library rather than markup tied to one host. `UI.Common` is
a render-mode-agnostic Razor Class Library that holds the pages, the components and the typed API
client, and the `UI.Web` host that renders it stays thin. Another head, such as a .NET MAUI Blazor
Hybrid app, could then reuse the screens; none ships
([ADR-0015](adr/0015-blazor-everywhere-shared-ui.md), [ADR-0012](adr/0012-presentation-structure-common-libraries.md)).

## Where do I choose the options?

When you create the solution: as flags of `dotnet new trellis` (`dotnet new trellis --help` lists
them), or as options in the Visual Studio and Rider new-solution dialogs. `--skip-restore` is hidden
in Visual Studio (`.template.config/ide.host.json`). The options table of the
[README](../README.md) lists each one with its default and what it does.

## Why is the website not built with Blazor?

The website is pages of Markdown that must read without JavaScript and host as static files on GitHub
Pages, where Blazor WebAssembly would download its runtime before the first page of text and Blazor
Server would need a server the site does not have
([ADR-0031, amendment of 2026-10-26](adr/0031-documentation-site.md#amendment-2026-10-26-why-not-blazor)).
