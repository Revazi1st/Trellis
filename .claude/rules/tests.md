# Testing rules

Which project a test belongs in, what each one proves and needs: `docs/development.md` (*Tests*), the canonical map. These are the conventions inside them.

- **xUnit v3** + **Shouldly** (`value.ShouldBe(...)`). Mocks: **NSubstitute**. Never FluentAssertions or Moq.
- Test names are a sentence about the behaviour, its words joined by underscores (`An_unregistered_unique_violation_throws_out_of_the_commit_and_writes_nothing`): the form most of the suite uses. Some older files name tests `Method_Scenario_Outcome` (`EveryMustRule_NamesItsErrorCode`); stay consistent inside a file and write a new file in the sentence form.
- **Results in tests**: assert success with `ShouldBeSuccess()` from `tests/TestSupport/ResultAssertions.cs` (namespace `Trellis.TestSupport`, `[ShouldlyMethods]`): `void ShouldBeSuccess(this Result, string? customMessage = null)` and `T ShouldBeSuccess<T>(this Result<T>, …)`, which returns the value. A failure throws `ShouldAssertException` naming the asserted expression, the error's code, type and description, and every child error of a `ValidationError`, field first; `ResultAssertionsTests` (Domain.UnitTests/SharedKernel) pins that message. The file is compiled into Domain.UnitTests, Application.UnitTests, IntegrationTests and ApiTests by `<Compile Include="..\TestSupport\ResultAssertions.cs" Link="TestSupport\ResultAssertions.cs" />` plus `<Using Include="Trellis.TestSupport" />` in each csproj: linked source, no shared test project.
  - Never `result.IsSuccess.ShouldBeTrue()` (it fails with "should be True but was False"), and never `.Value` on an arrange step. A test about a failure asserts on `Error` (`result.Error.ShouldBe(InvoiceErrors.NotDraft)`). The two exceptions: `Domain.UnitTests/SharedKernel/ResultTests.cs` tests `IsSuccess` itself, and `ApiTests/Ui` asserts the UI's own `ApiResult<T>`, not a SharedKernel `Result`.
  - RSLT001 covers tests too (the analyzer every project loads, ADR-0030): a dropped `Result`, `Error`, UI `ApiResult<T>` or `IdentityResult`, an awaited one included, fails the Release build, so an arrange step ends in `.ShouldBeSuccess()` and an Identity call in a fixture goes through `IdentitySeed.EnsureSucceeded`. A test that reads only what a use case or a UI client call leaves behind (a log line, a span, a recorded request) asserts its result anyway or drops it with `_ = …` and a one-line reason. Exempt: NSubstitute's call check (`await uow.Received(1).CommitAsync(ct)`), a chaining assertion (`result.Error.ShouldBeOfType<ValidationError>()`) and the body of `Should.ThrowAsync(() => handler.Handle(...))`; a call inside `Received.InOrder(...)` or `When(...)` is not, and neither is `Should.NotThrow(() => ...)`, which hands back the dropped result.
- **Arrange with factories and drivers** (ADR-0009 amendment): the state a test starts from comes from the helpers below. The drivers are arrange-only, one method per use case, with no generic `SendAsync` (a mediator by another name): a test about a use case's outcome calls the handler or sends the request itself and asserts on what comes back. Pass every value the test asserts on at the call site, never leave it to a default (the `"usd"` normalisation, an asserted amount, an explicit due date). A new feature gets its own `<Feature>Factory` in `tests/TestSupport/<Feature>/` and its drivers beside these, never in a toggle-conditional file.
  - **A valid command or aggregate**: `InvoiceFactory` (`tests/TestSupport/Invoices/InvoiceFactory.cs`, namespace `Trellis.TestSupport.Invoices`, a static class compiled into Application.UnitTests and IntegrationTests only, by `<Compile Include="..\TestSupport\Invoices\InvoiceFactory.cs" Link="TestSupport\Invoices\InvoiceFactory.cs" />`). Commands `CreateCommand(...)`, `AddLineCommand(invoiceId, ...)` and `IssueCommand(InvoiceId invoiceId, DateTimeOffset dueDate, uint? expectedVersion = null)` (no default due date: the handler's clock decides whether it is past); aggregates `Draft(customerName, customerEmail, currency)`, `DraftWithLine(...)`, `Issued(dueDate?, issuedAt?, customerName)`, `Paid(...)` and `Voided(customerName)`. Every value is an optional parameter, every step is checked with `ShouldBeSuccess()`, and the aggregates keep the events their transitions raised (`ClearDomainEvents()` for one that looks freshly loaded). The clock constants are `IssuedAt` (2026-07-15), `DueDate` (2026-08-01) and `PaidAt` (2026-07-20 12:00). `DecoratorPipelineTests` and the handler tests build through it.
  - **An invoice in a given state against PostgreSQL**: `InvoiceDriver` (`tests/Trellis.IntegrationTests/InvoiceDriver.cs`, `internal static class`), `IServiceProvider` extensions returning `Task<InvoiceId>`: `CreateInvoiceAsync`, `AddInvoiceLineAsync`, `IssueInvoiceAsync(services, invoiceId, DateTimeOffset? dueDate = null)` (due 14 days after the container's `TimeProvider` by default), `PayInvoiceAsync`, `VoidInvoiceAsync` and the `IssuedInvoiceAsync` shortcut. Each resolves the real handler, so the command runs the whole pipeline, and fails naming the error.
  - **An invoice over HTTP**: `InvoiceHttpDriver` (`tests/Trellis.ApiTests/InvoiceHttpDriver.cs`, `internal static class`), `HttpClient` extensions returning `Task<Guid>`: `CreateInvoiceAsync` (a fresh key through `PostWithIdempotencyKeyAsync`), `AddInvoiceLineAsync`, `IssueInvoiceAsync(client, Guid invoiceId, DateTimeOffset dueDate)`, `PayInvoiceAsync`, `VoidInvoiceAsync`. A refused request fails naming the method, path, status, problem `code` and body, through `HttpResponseAssertions.ShouldAnswerAsync(expected)`, which every `{Feature}HttpDriver` shares.
- **Domain.UnitTests**: pure, no mocks. `StronglyTypedIdParsingTests` is a theory over every `IStronglyTypedId<>` in the Domain, found by reflection (a version-7 `New()`, the `Parse`/`TryParse` round trip, text that is not a `Guid` turned down; control: a planted lenient ID), so a new ID needs no test of its own. **Application.UnitTests**: handlers/decorators with faked ports (`Substitute.For<...>`), `FakeTimeProvider` for time. `CommandValidatorConventionTests` lives here because it needs the registered validators: every command with string input has one, and every `Must`/`MustAsync` names its code with `.WithErrorCode("Area.Problem")` (an uncoded predicate would reach clients as `Validation.Predicate`), with `TheMustRuleCheck_FlagsOnlyTheUncodedPredicates` as its control.
  - One folder per use case, mirroring the slice: `tests/Trellis.Application.UnitTests/Features/<Feature>/<UseCase>/<UseCase>CommandHandlerTests.cs` (a query's `<UseCase>QueryHandlerTests.cs`); Invoices has `AddInvoiceLine`, `CreateInvoice`, `GetInvoice`, `IssueInvoice`, `ListInvoices`, `ListOverdueInvoices`, `PayInvoice`, `VoidInvoice` and `EventHandlers/SendReceiptOnInvoicePaidTests.cs`. Namespaces follow the folders (`Trellis.Application.UnitTests.Features.Invoices.VoidInvoice`).
  - The validators' bounds sit in `Features/<Feature>/<Feature>CommandValidatorTests.cs` (`Features/Invoices/InvoiceCommandValidatorTests.cs`): the maximum accepted and one more rejected naming the property, driven by the Domain constant, never a literal (`Invoice.CustomerNameMaxLength`, `EmailAddress.MaxLength`, `Currency.CodeLength`, `InvoiceLine.DescriptionMaxLength`), plus the amount floor, the required due date, both lists' paging bounds (page 1..10000, pageSize 1..100) and the list's defined statuses. A new list needs no paging rows of its own: `EndpointContractTests.Every_paged_list_holds_its_documented_bounds_at_the_wire` sends each bound and one past it to every GET the served document gives a `page` and a `pageSize`.
  - Trap: `Trellis.Application.UnitTests.Features` shadows `Trellis.Application.Features`, so a partially qualified `Features.Invoices.X` written inside `Trellis.Application.UnitTests` no longer resolves. Import the namespace with a using directive.
- **IntegrationTests**: real PostgreSQL via `IntegrationTestBase` (Testcontainers + Respawn) — exercise the real Application pipeline against a real DB. **Do not mock EF or the DbContext.** Includes the migration-drift guard (`HasPendingModelChanges` — a model change without a migration fails here) and the domain-event serialization fitness test. `UniqueConstraintTests` keeps the constraint map honest: a violation of a constraint `UniqueConstraintErrors` does not register throws out of `CommitAsync` and writes nothing, and a registered one through the same commit is its mapped `Result`; it walks the model too, every unique index and key registered or a fault on purpose with its reason (`FaultOnPurpose`) and every name in either list still in the model, with a planted model as its control (`The_model_walk_flags_…`).
  - Arrange through `InvoiceDriver` on the test's `Services`, or on a fresh scope's `ServiceProvider` for a separate unit of work (`OutboxTests` pays in a scope of its own).
  - The host runs as `IntegrationTestBase.CurrentUser`, a `TestCurrentUser` (`internal sealed class TestCurrentUser : ICurrentUser`: settable `UserId`, a v7 `Guid`, and `UserName`, default `TestCurrentUser.DefaultUserName = "integration-tests"`) registered as the `ICurrentUser` singleton. Set `UserId` to act as someone else (the audit columns record the id), or set it to `null` with a `UserName` to act as a caller without one, as the migration job does (`AuditingInterceptorTests`); a host a test builds itself registers a `TestCurrentUser` of its own (`TenancyTests`, with multi-tenancy).
- **ArchitectureTests**: `LayerDependencyTests` for boundaries — add a rule when you introduce one. A new project is anchored too: `Every_project_under_src_is_anchored_in_ArchitectureRules` reads the `.slnx` and fails on a project under `src/` that no `Assembly` property of `Architecture` (`ArchitectureRules.cs`, read by reflection) anchors, unless its allowlist names it with a reason (`UI.Web`, a host booted by `WebHostTests`); its control is a planted solution line (`The_anchor_check_flags_a_project_under_src_that_no_rule_loads`). ServiceDefaults depends on no layer (`ServiceDefaults_depends_on_no_solution_layer`). `ConventionTests` enforce the rules files — a new convention gets a test, not just prose:
  - by reflection: sealed non-public handlers that inject neither another `ICommandHandler` nor `IUnitOfWork` (a use case never runs another one's pipeline) and live only in Application (Scrutor decorates only what `AddApplication()` registers), `internal sealed` endpoints, value objects shaped `Create → Result<T>` with no public constructor (so no positional record) and no public `set` or `init`, aggregate encapsulation (no public constructors or setters), every `AggregateRoot<>` created through a static `Create` returning `Result<TAggregate>` (internal when only its parent aggregate creates it) and no other public static method handing back the bare aggregate (controls: `PlantedViolations.AggregateWithoutFactory` and `AggregateWithBareFactory` are refused, `AggregateCreatedByItsParent` passes), sealed-record events, and a unique lowercase-dotted `[DomainEventHandlerName]` on every domain-event handler (the outbox's completion key);
  - by source scan (`RepositorySource`; each scan keeps a path-keyed allowlist with reasons, a stale entry fails it, `SourceScan` holds both halves): every catch filter that lets `OperationCanceledException` through keys on the host or request token (`cancellationToken` / `stoppingToken`, never a linked token) across `src/` and `tools/`; `IgnoreQueryFilters()` is never called bare across `src/`, `tools/` and `tests/`; no `throw` in the Domain, Application's `Features/` (outside `EventHandlers/`) or the Api's `Features/` (`Money.cs` allowlisted: cross-currency arithmetic is a programmer error; control `The_throw_scan_flags_…`); no `DateTime(Offset).UtcNow`/`Now`, `DateTime.Today` or `Guid.NewGuid` (called or as a method group) in `src/` or `tools/`, `.cs` or `.razor` (control `The_clock_scan_flags_…`); no `Thread.Sleep` or timed `Task.Delay` in `tests/` (a delay of `Timeout.Infinite` waits for cancellation and passes; control `The_sleep_scan_flags_…`, its rows assembled from two literals so the control file does not trip it); and no `PagedResponse` built in `src/` outside Api.Common's `PagedResponseMappings`, by a constructor call or a method declared to return one (control `The_paged_envelope_scan_flags_…`);
  - by source scan of the UI rules (`UiConventionTests`, with the UI): no endpoint `[Authorize]`, no `HttpClient` built (in any spelling) or injected outside `AddSharedUi` and no page or layout POST, no inline `<script>`, each fact with its `The_scan_flags_…` theory;
  - by source scan of the UI (`DesignSystemTests`, with the UI; `RepositorySource.RazorAndCssFiles` reads the `.razor` and `.css` files with Razor, HTML and CSS comments and full-line C# `//` comments stripped, a `//` after code on its line kept as part of an address, and line endings normalised): only `tokens.css` writes a colour, every colour token is one `light-dark()` pair and the theme blocks set only `color-scheme`, text passes AA on its grounds and every `--on-*` on its fill (WCAG arithmetic in the test), every class a page uses has a rule and every rule its subsection in `docs/design-system.md`, every `var(--x)` is declared, and the doc's token tables and the token file name the same tokens, both ways (the `TelemetryNamingTests` shape), with every `--name` code span anywhere in the doc a declared token, and the JSON export `scripts/export-design-tokens.sh` writes names every token in the file's order with both values and the doc's *Role* as its usage (`The_token_export_names_every_token_with_both_values`, skipped on Windows, where there is no `/bin/sh`); each fact has a positive control (`The_scan_flags_…`, `The_contrast_check_flags_…`, `The_*_reader_takes_…`);
  - by source scan of values (`SourceConstants` resolves a literal or a `const string` declared in the same file or in `Type.cs`): `ErrorCodeVocabularyTests` reads every `Error.<Type>(` factory, `.WithErrorCode(` and `ProblemDescriptor` row under `src/` and `tools/` and requires the `Area.Problem` shape, one `ErrorType` per code, and no catalogue code that doubles as an `Error`'s; a code computed outside the SharedKernel fails as undeclared, so a new code is a literal or a `const string`;
  - **the analyzer** (`Analyzers/ResultDiscardAnalyzerTests`): RSLT001 runs over compiled snippets, one row per shape it reports and per shape it leaves alone, and a new shape gets a row; the wiring fact checks that `Directory.Build.props` loads it into every project under `src/`, `tests/` and `tools/`; its positive control compiles real Domain, Application and SharedKernel drops under the repository's own `.editorconfig` with warnings as errors, as a Release build does; and the suppression scan (`Nothing_in_the_repository_silences_RSLT001`) finds a `#pragma warning disable` naming it or bare, a `[SuppressMessage]`, a `<NoWarn>`/`<WarningsNotAsErrors>` entry, `RunAnalyzers`/`RunAnalyzersDuringBuild`/`TreatWarningsAsErrors` set to false, or a severity below warning in a nested `.editorconfig`/`.globalconfig`, on the rule's own line or a bulk one (every analyzer's, or its category's), with one control row per form (`The_suppression_scan_flags_each_way_to_silence_the_rule`); the root `.editorconfig` names RSLT001's severity itself, which outranks its generated-code section's bulk line (`The_root_editorconfig_pins_RSLT001_above_every_bulk_severity_line`);
  - **the container images** (`ContainerImageTests`, ADR-0011): every image the AppHost declares (each `Add<Resource>(`'s default image, the tool tiles, `AddContainer` and `WithImage` literals) and every `image:`, `container:` or `docker://` in the workflows and the root compose file, comments included, is on `ImageAllowlist` with its license (`Every_container_image_the_AppHost_declares_is_on_the_allowlist`); controls `The_image_scan_flags_an_image_off_the_allowlist` and `The_image_reader_takes_the_full_name_without_tag_or_digest`;
  - **the license ceilings** (`LicenseCeilingTests`, ADR-0011): `LicenseCeilingPackageIds` in `Directory.Build.props`, the LICENSE CEILINGS comment in `Directory.Packages.props` (every id named, every bullet above its version-only line in the list) and Dependabot's whole-package ignores name the same ids; control `The_ceiling_check_flags_an_id_missing_from_any_of_the_three`;
  - **positive controls**: each rule also runs against the shape it exists to refuse, because a rule that passes a clean codebase and a broken check alike proves nothing. `PlantedViolations` holds the broken types (named without `Invoice`, so `remove-feature` leaves them alone), the scans have rows that must be flagged (`The_scan_flags_…`, `The_bare_query_filter_scan_tells_a_bare_call_from_a_named_one`), and `RepositorySourceTests` pins the comment stripping every scan relies on. A new rule lands with its control.
  - **a new scan** is a `RepositorySource` read, a path-keyed allowlist whose values are the reasons, `[GeneratedRegex]` with a timeout, `scannedFiles.ShouldNotBeEmpty()`, and a `[Theory]` control; a control row that sits in a file the scan reads assembles the forbidden text from pieces, and none writes a template directive token whole.
  `NamingConventionTests` cover namespace-mirrors-folder, the `Async` suffix (SharedKernel is exempt: `Handle`/`Bind`/`Map` are named after their patterns) and role suffixes. `OptionsConventionTests` require a validation attribute on every `*Options` type and boot the real API host to prove each is validated at start (and that an out-of-range value stops it naming the key); a section owed only while a sibling setting selects it (`Email:Smtp` while `Email:Provider` is `Smtp`) is checked by its own `IValidateOptions<T>`, with a boot row per broken relay setting and rows proving another provider leaves it unchecked. `TelemetryNamingTests` keep meters, sources, instruments and attributes on the `Trellis.*` / `trellis.*` prefixes with units, and hold the telemetry reference in `docs/deployment.md` to the code both ways: every documented name, unit and event id exists, and every one in the code is documented; no log message template names `CallerUserId`, the caller's log scope (a message names the account it is about `{UserId}`).
- **ApiTests/InProcess**: `ApiFactory` (`WebApplicationFactory` + Testcontainers PostgreSQL) runs the **real HTTP pipeline** — JWT 401/403, permission policies (each endpoint's one permission pinned in `EndpointMetadataTests.ExpectedPermissions`, beside `AnonymousAllowlist` and `AuthenticatedOnly`, and proved on the wire by a theory that calls every endpoint with only its permission and then with every other one), idempotency (replay, fingerprint 422, in-flight and duplicate 409, nothing reserved by a failed command; `EndpointContractTests` reads `IdempotencyErrors.MultipleKeys` from `Trellis.Application.Abstractions`, the one owner of every `Idempotency.*` code), the auth rate limit, the RFC 9457 shape (`ProblemDetailsContractTests`: one test per status, every body deserialised into `ProblemResponse`; a new status or `code` gets a row there) — inside the SDK container on every `test` run. Aspire E2E stays opt-in (`RUN_ASPIRE_E2E=1`), sits in `AspireE2ECollection` (`DisableParallelization`, so it runs alone after the parallel collections) with `[Trait("Category", AspireE2ECollection.Category)]` (CI runs the tag as its own step after the other projects: the AppHost's processes and Testcontainers race for host ports otherwise; an Aspire test of yours takes both attributes) and calls `appHost.UseThrowawayDatabase()` (`AppHostTestingExtensions`, pinned by `ThrowawayDatabaseTests`) before it builds the AppHost, so it never opens the developer's persistent database; contract-serialization guards are always on. What the AppHost declares is read from its app model without starting it, in the SDK container on every run: `AppHostMailTests` creates the builder (`DistributedApplicationTestingBuilder.CreateAsync`, `["--operation", "publish"]` for publish mode), never builds it, and evaluates a resource's environment with `ExecutionConfigurationBuilder.Create(resource).WithEnvironmentVariablesConfig().BuildAsync(new DistributedApplicationExecutionContext(DistributedApplicationOperation.Publish), NullLogger.Instance, ct)` (a publish-time evaluation, so an endpoint stays an `EndpointReferenceExpression` rather than waiting for a port; the logger is required, since the context has no services). The SMTP adapter is driven over a fake relay on a loopback socket (`EmailSenderTests.FakeRelayAsync`: no extensions advertised, so no STARTTLS and no AUTH). The fixture contract (ADR-0021): A test that expects the host to REFUSE to start (an option rejected at boot, an endpoint the Result guard refuses) goes through `BootFailure.OfAsync(() => factory.WithWebHostBuilder(…))` (`InProcess/BootFailure.cs`), never a bare `Should.Throw(() => host.CreateClient())`: the top-level `Program` is started on a second thread, and a `CreateClient` that loses the race against that thread's dispose sees `ObjectDisposedException` instead of the boot error; the helper retries that case on a fresh host and hands back the real exception (`BootFailure.Unwrap` flattens it).
  - Every `CreateClient()` calls from its own simulated address (`ApiFactory.ClientAddressHeader`, applied by an outermost startup filter), so each client is its own anonymous rate-limit partition and no test spends another's `auth` budget. Model many users behind one host with `CreateClientFrom(address)`.
  - Fixtures state `Registration:Mode=Open`, and a host setting cannot be unset; a test about shipped defaults boots a plain `WebApplicationFactory<Program>` instead (`AuthFlowTests.Register_WithTheShippedProductionConfiguration_IsClosed`).
  - Kestrel-only behaviour (request-size limits) runs on a real listener: `RequestLimitTests.KestrelApiFactory` (in `EndpointMetadataTests.cs`) calls `UseKestrel(0)`, because TestServer does not enforce Kestrel limits.
  - `AuthFlowTests.Factory` swaps in observers instead of mocks: an adjustable clock (token expiry), a counting password hasher (timing oracle), a capturing `ILoggerProvider` (security events).
  - Move time, never sleep: `ApiFactory.Time` is a settable clock registered as the host's `TimeProvider` — `Advance(...)` it and `Reset()` it in a `finally`, because the fixture is shared (`TenantIsolationTests` makes an invoice overdue this way; a derived factory's own clock still wins).
  - A caller with exactly the permissions a test names: `ApiFactory.CreateClientWithPermissions(params string[])` mints through the host's own `ITokenProvider` (no Identity row, no login spent against the rate limit); `CreateAdminClientAsync` and `CreateMemberClientAsync` sign in for real. The tokens `EndpointMetadataTests` builds by hand are invalid on purpose (another algorithm, another key) and stay hand-built.
  - Arrange steps: an invoice in an arrange step comes from `client.CreateInvoiceAsync()` and the other `InvoiceHttpDriver` steps. A test about the create's own answer sends it with `PostWithIdempotencyKeyAsync` (`IdempotentPostExtensions`), because `POST /invoices` declares `RequireIdempotency(keyRequired: true)`; a test about the key builds its request by hand.
  - Assert a header so that its absence fails: `response.ShouldBeProblemJson()` or `ShouldHaveMediaType(...)` (`HttpResponseAssertions`), never `Content.Headers.ContentType?.MediaType.ShouldBe(...)`, which never runs when the header is missing.
  - **Api.Common's internals are visible to this project** (`InternalsVisibleTo` in `Trellis.Api.Common.csproj`): host plumbing nothing on the wire can reach — a forged request line in the exception handlers' and `CompletingResult`'s log lines — is driven on a `DefaultHttpContext` with a capturing `ILoggerProvider`, at the project root beside the other Docker-free tests (`LogSafeRequestLineTests`).
- **ApiTests/Ui** (absent with `--include-ui false`): UI.Common's clients and token provider over a scripted handler and a manual clock (`UiHarness`); every file sits behind the `IncludeUI` conditional and the csproj references UI.Common under the same guard.
- **OpenAPI** (ADR-0025): `OpenApiSnapshotTests` (in-process) proves `docs/api/openapi.v1.json` is the document the API serves — any wire change fails every `dotnet test` run until you regenerate (`UPDATE_OPENAPI_SNAPSHOT=1 dotnet test tests/Trellis.ApiTests`, forwarded by `scripts/dotnet.sh`, or `scripts/export-openapi.sh` against a running API; the committed bytes are the server's serialisation plus a final newline) and commit the diff. `OpenApiDocumentTests` gate the document's content: summary **and** description on every operation, probes out, a unique `operationId` per operation (the endpoint class), no `{version}` or `servers`, every 4xx/5xx `$ref`-ing `ProblemResponse` (which requires only `type`/`title`/`status`/`code`), 400/404 by shape, the Result statuses of the anonymous auth operations (declared with a bare `.Produces(status)`), `Location` on 201, `If-None-Match`/`ETag`/304 on a conditional GET, an optional `If-Match` and the 412 on every conditional write (`Conditional_writes_document_an_optional_If_Match_and_412`), `If-Match` on every write under a GET that answers an `ETag` (`Every_write_to_a_resource_that_answers_an_ETag_takes_If_Match`, the exemptions with their reasons in `WritesWithoutIfMatch`, control `The_If_Match_check_flags_an_unconditional_write_under_a_versioned_resource`), camelCase bounded paging, string-enum status / decimal money / int64 version. `InvoiceContractTests` proves those promises on the wire (304 for weak, strong, list and `*` tags; a stale, weak, listed or foreign `If-Match` is a 412 that changes nothing; a zero-padded `"0{version}"` `If-Match` is a 412 even when it equals the current version; a missing invoice is a 404 for a well-formed `If-Match` and a malformed one is a 412 before the lookup (`A_missing_invoice_is_a_404_for_a_well_formed_If_Match_and_a_malformed_one_is_a_412_before_the_lookup`: `"7"` → 404, `"07"` → 412, `W/"7"` → 412); `GET /invoices/{id}` answers `private, no-cache` on the 200 and the 304 while both lists stay `no-store` (`Get_invoice_lets_a_browser_keep_and_revalidate_it_while_other_reads_stay_no_store`); paging bounds answer 400 naming the field on both lists; `Location` resolves; a created-then-issued invoice heads `GET /invoices` and is absent from the overdue list). The `no-store` default itself is `EndpointMetadataTests.Api_responses_are_not_stored_by_a_cache_unless_the_endpoint_says_otherwise`, which reads `GET /invoices/overdue`. A Contracts enum that mirrors a domain enum gets a `ContractMirrorTests` fact in ArchitectureTests.
- Use `TestContext.Current.CancellationToken` for cancellable calls.
- **Aspire resource names** come from `ServiceNames` (ServiceDefaults) in a test as in the hosts: `$"ConnectionStrings:{ServiceNames.Database}"`, `WaitForResourceHealthyAsync(ServiceNames.Api, ct)`. A literal still compiles after a rename and fails only when the test runs.
