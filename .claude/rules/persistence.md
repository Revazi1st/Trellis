# Persistence layer rules

Peer of Infrastructure — **never reference `Trellis.Infrastructure`** (arch-test enforced). Owns EF Core, migrations, and Identity.

- **Configurations**: one `IEntityTypeConfiguration<T>` per aggregate in `Configurations/`. Value objects → `ComplexProperty` (EF 10 complex types). Aggregates load whole: `AutoInclude()` child navigations + `UsePropertyAccessMode(Field)`.
- **Strongly-typed IDs**: add one line to `AppDbContext.ConfigureConventions` per new ID.
- **A value object that needs an index, a key or `Contains`** is a converted column, not a complex type (EF Core 10 cannot index a complex-type member): it implements `IScalarValueObject<TSelf, TValue>` and gets one line in `AppDbContext.ConfigureConventions`, `Properties<T>().HaveConversion<ScalarValueObjectConverter<T, TValue>>()`, which converts every member of that type. The rule, not the default (ADR-0006): queries then compare the whole value but cannot reach inside it (`Email.Value.StartsWith` stops translating), and switching a type is a model change with a migration.
- **Interceptors** (`Interceptors/`) do cross-cutting persistence work — the outbox write (`OutboxWriteInterceptor` turns raised domain events into `OutboxMessages` rows in the same transaction; no handler runs during `SaveChanges`), soft-delete, auditing and, with multi-tenancy, tenant stamping. Order is fixed in `DependencyInjection.cs`; the one exception is `AggregateConcurrencyInterceptor`, which `AppDbContext.OnConfiguring` attaches after them so no context instance runs without it.
- **Concurrency guards the whole aggregate**: every aggregate root maps a concurrency token (`xmin`, as `InvoiceConfiguration` does), and a change to its children alone marks one real root column modified, so the root's UPDATE checks and bumps the token whether or not the root is `IAuditable` (`AggregateConcurrencyInterceptor`; `AggregateConcurrencyTests` fails a root without a token). A stale token is `Concurrency.Conflict` (409) from `CommitAsync`.
- **Unique constraints**: a violation is a fault (500) unless its constraint is registered by name in `UniqueConstraintErrors` — `PK_IdempotencyKeys` and Identity's `UserNameIndex` today — which `CommitAsync` and `IdentityService` turn into the mapped `Result`. Register one by pinning the name in its configuration, adding the row, and racing it in a test; never match "any unique violation" (ADR-0018) — `UniqueConstraintTests` puts an unregistered one through `CommitAsync` and fails unless it throws.
- **Soft delete**: implement `ISoftDeletable`; the interceptor + the `"SoftDeleted"` named query filter handle it. Use `IgnoreQueryFilters(["SoftDeleted"])` for admin views.
- **Multi-tenancy** (toggle): scoping is convention-based — `AppDbContext.OnModelCreating` gives every `IHasDomainEvents` entity type (every `AggregateRoot<>`) the `TenantId` shadow column, its index and the named `"Tenant"` filter. **Never add tenant columns or filters in a configuration**; a deliberately shared aggregate is an explicit opt-out decision (ADR-0022). Identity tables stay unfiltered on purpose. Opt out of the filter per query with `IgnoreQueryFilters(["Tenant"])`, never the bare overload (it drops `"SoftDeleted"` too). `TenancyTests` is the fitness test.
- **Outbox** (ADR-0023): rows store the event's `[DomainEventName]` wire name (`DomainEventSerialization.TypeNameOf`), plus `TenantId` and `TraceParent`; never persist a CLR type name. The processor claims with the `FOR UPDATE SKIP LOCKED` SQL and its partial index (keep both as they are), **leases** the rows by stamping `NextAttemptAtUtc` (no extra column), and dispatches each message in its own scope outside the claim transaction, restoring `AmbientTenant` around it and committing after every handler through the dispatcher's `checkpoint` — "credited" means "durable". The lease is also the fence: `NextAttemptAtUtc` is the row's concurrency token (`OutboxMessageConfiguration`), so every bookkeeping save — checkpoint, Processed, back-off, dead letter — is conditional on the lease this processor stamped, and a set-based write (the lease hand-back) repeats it in its `WHERE`. A stale processor, whose lease expired and was claimed again, affects no row and books `lease_lost` (log line, `trellis.outbox.outcome`) instead of resurrecting a Processed row or dead-lettering the new owner's. The dispatcher's `onHandlerFailed` hook isolates sibling handlers: a handler that throws has its uncommitted writes dropped from the tracker (the message re-attached with its lease), the handlers after it still run and checkpoint, and only it is retried. Unreadable rows (`OutboxErrors`) dead-letter at once as a `Result`; knobs live in `OutboxOptions` (`Outbox` section, options pattern below); the back-off is `OutboxBackoff`. Re-drive is SQL (deployment.md), not an endpoint. `OutboxRetryTests` is the fitness suite.
- **Background services** key their catch filters on the host token: `when (e is not OperationCanceledException || !stoppingToken.IsCancellationRequested)` — never on a linked token — and do their post-side-effect bookkeeping with `CancellationToken.None`. A scheduled retry logs Warning (with the exception); Critical is for a dead letter.
- **Race-sensitive single-row writes are one conditional `ExecuteUpdate`**, not read-check-write — `RefreshTokenStore.ConsumeAsync` is the reference (exactly one of two concurrent replays wins).
- **Bookkeeping tables** (processed outbox, idempotency keys, dead refresh tokens) are pruned by `DataRetentionJanitor` (ADR-0027); windows live in `RetentionOptions` (`Retention` section) — a new grows-forever table gets a sweep there, and a seeded row either side of its cutoff in `DataRetentionJanitorTests`. Sweeps stay set-based (`ExecuteDelete`) and never touch pending outbox rows.
- **Options** (`RetentionOptions` is the reference): bind in Persistence with `services.AddOptions<T>().Bind(configuration.GetSection(T.SectionName))` — never `Get<T>() ?? new T()` — state every limit as a DataAnnotation on the POCO (`[Range(typeof(TimeSpan), …)]` with an `ErrorMessage` naming the key), and project the POCO (`AddSingleton(sp => sp.GetRequiredService<IOptions<T>>().Value)`). Persistence does not reference the DataAnnotations options extension, so **the host that runs the service validates it**: `AddOptions<T>().ValidateDataAnnotations().ValidateOnStart()` in its `Program.cs`. Cross-field rules go next to the binding as `.Validate(predicate, "Section:Key must …")`. `OptionsConventionTests` builds the real API host and fails on an `*Options` type without a `ValidationAttribute` or without a registered `IValidateOptions<T>`.
- **Instants are UTC**: `ConfigureConventions` maps every `DateTimeOffset` (nullable too) through `UtcDateTimeOffsetConverter`, because Npgsql rejects a non-zero offset for `timestamptz`. Do not add per-property conversions.
- **Migrations are generated, never hand-edited**. Create with `./scripts/ef.sh migrations add <Name> --project src/Infrastructure/Trellis.Persistence` (see the `add-migration` skill). Regenerate the initial migration on the current EF version rather than accumulating churn pre-release.
- **Identity** lives in `Identity/` (ADR-0007): `ApplicationUser`, `IdentityService`, refresh-token store, and `IdentitySeed` (the MigrationService's idempotent seed). UserManager/RoleManager report failure as an `IdentityResult` — never discard one: map it to a `Result` in a use case, `IdentitySeed.EnsureSucceeded` it in the seed. Several Identity writes that must stand or fall together (account + role) run in one transaction inside `CreateExecutionStrategy().ExecuteAsync` (`RegisterAsync`).
