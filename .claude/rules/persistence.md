# Persistence layer rules

Peer of Infrastructure — **never reference `Trellis.Infrastructure`** (arch-test enforced). Owns EF Core, migrations, and Identity.

- **Configurations**: one `IEntityTypeConfiguration<T>` per aggregate in `Configurations/`. Value objects → `ComplexProperty` (EF 10 complex types). Aggregates load whole: `AutoInclude()` child navigations + `UsePropertyAccessMode(Field)`.
- **Strongly-typed IDs**: add one line to `AppDbContext.ConfigureConventions` per new ID.
- **What only PostgreSQL understands lives in `PostgresDialect.cs`** (ADR-0033): the provider, the token mapping, a store type by name (`HasColumnType`, `HaveColumnType`, a `[Column(TypeName)]`), a collation, an index filter, default or computed-column SQL, a check constraint, raw SQL through EF Core or ADO.NET, a provider extension method. A configuration, a repository or a service calls a member of it and never names the provider or writes SQL; prefer EF Core's own members (`HasMaxLength`, `HasPrecision`) to a store type. The migrations are generated and outside the rule. `DatabaseEngineTests` holds it twice: a scan of `src/`, `tools/` and `tests/` for the names and the calls, and a check of the compiled Persistence and Api assemblies for a provider member whose name does not say whose it is (lambdas and async methods included; in `tools/` and `tests/` only the scan looks). A place that cannot live in the dialect goes on its allowlist with the reason, and into `docs/switching-database.md`, which the same class holds to the list. Neither sees a connection string, a container a test starts through Testcontainers' generic `ContainerBuilder`, a store type or SQL handed to a member the pattern does not list, or the `If-Match` parser's `uint`.
- **A value object that needs an index, a key or `Contains`** is a converted column, not a complex type (EF Core 10 cannot index a complex-type member): it implements `IScalarValueObject<TSelf, TValue>` and gets one line in `AppDbContext.ConfigureConventions`, `Properties<T>().HaveConversion<ScalarValueObjectConverter<T, TValue>>()`, which converts every member of that type. The rule, not the default (ADR-0006): queries then compare the whole value but cannot reach inside it (`Email.Value.StartsWith` stops translating), and switching a type is a model change with a migration. Converting a type is a model change with a migration and a line in the feature doc; no ADR edit (`ConfigureConventions` is the list, ADR-0006's amendment of 2026-11-09).
- **Interceptors** (`Interceptors/`) do cross-cutting persistence work — the outbox write (`OutboxWriteInterceptor` turns raised domain events into `OutboxMessages` rows in the same transaction; no handler runs during `SaveChanges`), soft-delete, auditing and, with multi-tenancy, tenant stamping. Order is fixed in `DependencyInjection.cs`; the one exception is `AggregateConcurrencyInterceptor`, which `AppDbContext.OnConfiguring` attaches after them so no context instance runs without it.
- **Concurrency guards the whole aggregate**: every aggregate root maps a concurrency token (`PostgresDialect.MapRowVersion` on a `long Version`, as `InvoiceConfiguration` calls it: `xmin` behind a checked conversion; an expected version is compared in memory, as `InvoicePreconditions.ToWrite` does, or comes through `TryGetExpectedVersion`, because the conversion throws for a value the engine cannot hold), and a change to its children alone marks one real root column modified, so the root's UPDATE checks and bumps the token whether or not the root is `IAuditable` (`AggregateConcurrencyInterceptor`; `AggregateConcurrencyTests` fails a root without a token). A stale token is `Concurrency.Conflict` (409) from `CommitAsync`.
- **Unique constraints**: a violation is a fault (500) unless its constraint is registered by name in `UniqueConstraintErrors` (the map is the list; `PK_IdempotencyKeys` is the reference row; it reads the violated name through `PostgresDialect.TryGetViolatedUniqueConstraint`), which `CommitAsync` and `IdentityService` turn into the mapped `Result`. Register one by pinning the name in its configuration, adding the row, and racing it in a test; a unique index or key no two requests can race to is a fault on purpose instead, a row with its reason in `UniqueConstraintTests.FaultOnPurpose` (a single-column uuid or database-numbered primary key is one by its shape and needs none; the walk cannot tell a uuid a request chooses from one minted for the row, so an aggregate whose id a request supplies registers or lists its key by hand; with multi-tenancy that key is unique across every tenant, see *Multi-tenancy* below). `UniqueConstraintTests` walks the model and fails on a unique constraint that is neither registered nor declared a fault on purpose, and on a name the model no longer holds. Never match "any unique violation" (ADR-0018): the same tests put an unregistered one through `CommitAsync` and fail unless it throws.
- **Soft delete**: implement `ISoftDeletable`; the interceptor + the `"SoftDeleted"` named query filter handle it. Use `IgnoreQueryFilters(["SoftDeleted"])` for admin views.
- **Multi-tenancy** (toggle): scoping is convention-based — `AppDbContext.OnModelCreating` gives every `IHasDomainEvents` entity type (every `AggregateRoot<>`) the `TenantId` shadow column, its index and the named `"Tenant"` filter. **Never add tenant columns or filters in a configuration**; a deliberately shared aggregate is an explicit opt-out decision (ADR-0022). Identity tables stay unfiltered on purpose. Opt out of the filter per query with `IgnoreQueryFilters(["Tenant"])`, never the bare overload (it drops `"SoftDeleted"` too). A unique index on an aggregate root is unique per tenant: the convention puts `TenantId` first in every unique index of an `IHasDomainEvents` type, so a configuration still names no tenant and the pinned constraint name is unchanged; Identity's unique indexes stay global (one e-mail is one user in one tenant). Declare a business key as a unique index for that reason, and reference another aggregate by its id: an alternate key, declared with `HasAlternateKey` or made by `HasPrincipalKey` for a reference by another column, is never rewritten, so it would be unique across every tenant, and `TenancyTests` fails naming it. A value that needs a unique key is the converted column above, never an owned type: `OwnsOne` maps the value into the root's table as an entity type of its own, which the convention does not visit, so a unique index or key declared on it would be unique across every tenant, and `TenancyTests` fails naming that too. The convention stops at the root: a child table's unique index or alternate key that its root's id does not lead, and a primary key a request chooses, stay unique across every tenant, the 409 telling the caller that another tenant holds the value, and no test catches either; put the key on the root, lead it with the root's id or mint the id on the server, and give a key that stays global its line, with the reason, in the multi-tenancy gap of `docs/threat-model.md`. A row written with no tenant has a NULL `TenantId` and is outside the tenant-led indexes (PostgreSQL treats NULLs as distinct, so two tenant-less rows may hold the same key): a flow that writes an aggregate without a signed-in caller (a job, an anonymous endpoint, a webhook) sets `AmbientTenant.CurrentTenantId` around the write, as the outbox processor does. A key that must be unique across every tenant is a deliberate change to the convention loop (ADR-0022). `TenancyTests` is the fitness test.
- **Outbox** (ADR-0023): rows store the event's `[DomainEventName]` wire name (`DomainEventSerialization.TypeNameOf`), plus `TenantId` and `TraceParent`; never persist a CLR type name. The processor claims with the `FOR UPDATE SKIP LOCKED` SQL and its partial index (keep both as they are; both are members of `PostgresDialect`), **leases** the rows by stamping `NextAttemptAtUtc` (no extra column), and dispatches each message in its own scope outside the claim transaction, restoring `AmbientTenant` around it and committing after every handler through the dispatcher's `checkpoint` — "credited" means "durable". The lease is also the fence: `NextAttemptAtUtc` is the row's concurrency token (`OutboxMessageConfiguration`), so every bookkeeping save — checkpoint, Processed, back-off, dead letter — is conditional on the lease this processor stamped, and a set-based write (the lease hand-back) repeats it in its `WHERE`. A stale processor, whose lease expired and was claimed again, affects no row and books `lease_lost` (log line, `trellis.outbox.outcome`) instead of resurrecting a Processed row or dead-lettering the new owner's. The dispatcher's `onHandlerFailed` hook isolates sibling handlers: a handler that throws has its uncommitted writes dropped from the tracker (the message re-attached with its lease), the handlers after it still run and checkpoint, and only it is retried. What the processor writes into `Error` (a handler's exception message, a dead letter's reason) is made storable first, each lone surrogate and NUL replaced by U+FFFD (`StorableText`), because a save the database refuses for that text could never book the attempt (`StorableTextTests`, and `OutboxRetryTests` against the database). Unreadable rows (`OutboxErrors`) dead-letter at once as a `Result`; knobs live in `OutboxOptions` (`Outbox` section, options pattern below); the back-off is `OutboxBackoff`. Re-drive is SQL (deployment.md), not an endpoint. `OutboxRetryTests` is the fitness suite.
- **Background services** key their catch filters on the host token: `when (e is not OperationCanceledException || !stoppingToken.IsCancellationRequested)` — never on a linked token — and do their post-side-effect bookkeeping with `CancellationToken.None`. A scheduled retry logs Warning (with the exception); Critical is for a dead letter.
- **Race-sensitive single-row writes are one conditional `ExecuteUpdate`**, not read-check-write — `RefreshTokenStore.ConsumeAsync` is the reference (exactly one of two concurrent replays wins).
- **Bookkeeping tables** (processed outbox, idempotency keys, dead refresh tokens) are pruned by `DataRetentionJanitor` (ADR-0027); windows live in `RetentionOptions` (`Retention` section) — a new grows-forever table gets a sweep there, and a seeded row either side of its cutoff in `DataRetentionJanitorTests`. Sweeps stay set-based (`ExecuteDelete`) and never touch pending outbox rows.
- **Options** (`RetentionOptions` is the reference): bind in Persistence with `services.AddOptions<T>().Bind(configuration.GetSection(T.SectionName))` — never `Get<T>() ?? new T()` — state every limit as a DataAnnotation on the POCO (`[Range(typeof(TimeSpan), …)]` with an `ErrorMessage` naming the key), and project the POCO (`AddSingleton(sp => sp.GetRequiredService<IOptions<T>>().Value)`). Persistence does not reference the DataAnnotations options extension, so **the host that runs the service validates it**: `AddOptions<T>().ValidateDataAnnotations().ValidateOnStart()` in its `Program.cs`. Cross-field rules go next to the binding as `.Validate(predicate, "Section:Key must …")`. `OptionsConventionTests` builds the real API host and fails on an `*Options` type without a `ValidationAttribute` or without a registered `IValidateOptions<T>`.
- **Instants are UTC**: `ConfigureConventions` maps every `DateTimeOffset` (nullable too) through `UtcDateTimeOffsetConverter`, because Npgsql rejects a non-zero offset for `timestamptz`. Do not add per-property conversions.
- **Migrations are generated, never hand-edited**. Create with `./scripts/ef.sh migrations add <Name> --project src/Infrastructure/Trellis.Persistence` (see the `add-migration` skill), then review the generated `Up`/`Down` without editing them: a wrong one is removed (`migrations remove`) and generated again from the corrected model. The edit hook asks before any edit under `Migrations/`. Regenerate the initial migration on the current EF version rather than accumulating churn pre-release.
- **Identity** lives in `Identity/` (ADR-0007): `ApplicationUser`, `IdentityService`, refresh-token store, and `IdentitySeed` (the MigrationService's idempotent seed). UserManager/RoleManager report failure as an `IdentityResult` — never discard one: map it to a `Result` in a use case, `IdentitySeed.EnsureSucceeded` it in the seed. Several Identity writes that must stand or fall together (account + role) run in one transaction inside `CreateExecutionStrategy().ExecuteAsync` (`RegisterAsync`).
