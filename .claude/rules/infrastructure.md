# Infrastructure layer rules

Peer of Persistence — **never reference `Trellis.Persistence`** (ADR-0002, arch-test enforced). Anything touching EF/the database belongs in Persistence, not here.

- This project is **adapters for Application ports only** (`Abstractions/`): `JwtTokenProvider : ITokenProvider`, `SmtpEmailSender`/`LoggingEmailSender`/`DiscardingEmailSender : IEmailSender`, `ExchangeRateClient : IExchangeRateProvider`, `TimeProvider.System`. No business rules, no orchestration — those live in Application/Domain.
- Adapters are `internal sealed`; the public surface is the `DependencyInjection` extensions — `AddInfrastructure` (every host), `AddOutboundIntegrations` (hosts that call out: the API) and the host-policy `Require…` calls — plus the options types.
- **Options are bound from configuration in `AddInfrastructure`** (e.g. `AuthTokenOptions` from its `SectionName`) and registered as singletons — adapters take the options type, never `IConfiguration`.
- **Every options class carries DataAnnotations** (`[Required]`, `[Url]`, `[Range]`) and is bound with `AddOptions<T>().Bind(...).ValidateDataAnnotations()`. Never `Get<T>() ?? new T()` — that turns a missing section into silently-defaulted behaviour. Add `.Validate(predicate, message)` when the annotation's own message wouldn't tell you what to do about it. The one exception is `SmtpOptions`: its section is owed only while `Email:Provider` is `Smtp`, so it is bound without `ValidateDataAnnotations()` (which would check it whatever the provider) and its own `IValidateOptions<SmtpOptions>`, `SmtpOptionsValidator`, applies the annotations and the cross-field rules then and skips otherwise. Follow that shape for any section a sibling setting switches on.
- **`ValidateOnStart` is host policy, not adapter wiring.** `AddInfrastructure` binds and annotates; a host opts into boot-time failure (`RequireValidTokenOptions()`). The migration service shares this registration and must not need a JWT secret to run migrations.
- **Outbound HTTP** goes in `ExternalApis/<Provider>/` as a typed client behind an Application port returning `Result` (ADR-0020), registered from `AddOutboundIntegrations` — never `AddInfrastructure`: the standard resilience handler validates its options at boot, so registering a client makes its section a boot requirement of every host that has it. Rules that are not optional:
  - `HttpClient.Timeout = Timeout.InfiniteTimeSpan` — the resilience pipeline owns timeouts.
  - **Replace, don't add**: `RemoveAllResilienceHandlers()` (`EXTEXP0001`, suppressed with the reason) *before* the client's own `AddStandardResilienceHandler()`. Added alone, it nests inside ServiceDefaults' blanket handler, whose 10 s attempt timeout still wins and whose retries multiply the client's.
  - Configure the pipeline with `.Configure((o, sp) => …)` from the validated options, never a `Get<T>()` snapshot; cap `Retry.MaxDelay` and make the total timeout `attempt × (retries + 1) + maxDelay × retries`, or it cuts off the retries you granted.
  - Catch what the **pipeline** throws: `HttpRequestException`, Polly's `TimeoutRejectedException` (a timeout is not a `TaskCanceledException` here), `BrokenCircuitException` and other `ExecutionRejectedException`s, `JsonException`, and an `OperationCanceledException` only `when (!cancellationToken.IsCancellationRequested)` — the caller's own cancellation propagates.
- **External health checks cache their verdict and probe cheaply** (a TCP connect, not an application call), are registered as singletons, and report **Degraded** when the third party is down vs **Unhealthy** when our own config is wrong.
- **E-mail**: `Email:Provider` picks the adapter (`Smtp` — the BCL `SmtpClient` against `Email:Smtp`, one client per message, STARTTLS; `Logging` — the dev stand-in; `None` — discard). The sender is registered in every host (event handlers must be constructible); the API validates the section at boot — `Email:Smtp` only while `Smtp` is selected (`SmtpOptionsValidator` applies `SmtpOptions`' annotations itself, since `ValidateDataAnnotations()` would apply them whatever the provider) — and warns while the stand-in, or SMTP in clear, runs outside Development. Never log a message body or a full address: masked recipient (`j***@example.com`), subject, length. A failed send throws for the outbox to retry (the port returns `Task`; ADR-0004 holds), and what is thrown drops the relay's reply, which quotes the address. No implicit TLS (465) and no OAuth2: another provider (XOAUTH2, an HTTP API) is a new adapter in `Email/` plus an `EmailProvider` member.
- Keep it thin: one folder per concern (`Authentication/`, `Email/`), one adapter per port. If a class grows its own domain logic, it is in the wrong ring.
