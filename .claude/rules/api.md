# API layer rules

- **One endpoint per use case**, a class implementing `IEndpoint` (static-abstract `Map` returning the `RouteHandlerBuilder`) in `Features/{Feature}/`. Discovered by `MapEndpoints` onto the versioned `/api/v{version:apiVersion}` group (resolves to `/api/v1`), which names the route after the class — that name is the OpenAPI `operationId` (ADR-0025). Never call `.WithName` yourself; refer to another endpoint's route with `nameof(GetInvoice)`.
- Handlers are `static`, inject the Application handler interface, and return `Results<TSuccess, ProblemHttpResult>`. Map the `Result` with `result.IsSuccess ? TypedResults.X(...) : CustomResults.Problem(result.Error)`.
- **Never throw for expected failures** — everything flows as `Result` → `CustomResults.Problem` (RFC 9457). The global exception handler is only for unhandled faults. `ConventionTests.The_domain_the_use_cases_and_the_endpoints_return_a_Result_and_never_throw` finds a `throw` anywhere under the Api's `Features/`.
- **Problem details (ADR-0024)**: every 4xx/5xx is one shape — `code` (`Area.Problem`, what clients branch on), `type` = `urn:problem-type:{code}`, a human `title` (never parsed), `detail`, `instance`, `traceId`, `correlationId` (== `X-Correlation-ID`), and on every Result-produced 400 an `errors[]` of `{field, code, description}` (`field` = camelCase JSON path, `null` for a whole-request error). Never write a problem with `TypedResults.Problem` or `WriteAsJsonAsync`: a Result goes through `CustomResults.Problem(Error)`, anything else through `HttpContext.WriteProblemAsync(ProblemDescriptor)` with a `ProblemCatalog` row (add one for a new non-Result situation; the catalogue never carries a code an `*Errors` class owns). `UseStatusCodePages` + `ThrowOnBadRequest` are host plumbing — a bodyless status or a `BadHttpRequestException` is already a problem document, do not handle either per endpoint. A body string holding U+0000 is refused at JSON binding as 400 `Request.Malformed` naming the field (`NulFreeStringJsonConverter`, registered by `AddApiCommon`; PostgreSQL `text` stores none, and without it the NUL is a 500 from the first query or save), so no aggregate checks for it. The converter sees only the body: a route value cannot carry a NUL (Kestrel refuses `%00` in a path, `RequestLimitTests.A_NUL_in_the_path_is_refused_before_routing`), but a string bound from the query reaches the handler as sent, so a feature that binds one (a `?search=` filter) refuses U+0000 in its query's validator; `EndpointContractTests.Every_query_value_of_a_GET_refuses_a_NUL` sends one to every query value a GET takes. `ProblemDetailsContractTests` has one test per status; a new status or code gets a row there.
- **Bind `Api.Contracts` records**, not domain types or Application commands. Map contract → command in the handler.
- **Secure by default** (ADR-0021): every endpoint on the versioned group is authenticated by default (group `.RequireAuthorization()`, no fallback policy). Declare the permission with `.RequirePermission(Permissions.X.Y)` and pin it in `EndpointMetadataTests.ExpectedPermissions`; a name outside `Permissions.All` throws at startup. An endpoint that must be reachable without a token calls `.AllowAnonymous()` **and** is added to `EndpointMetadataTests.AnonymousAllowlist` — the test fails otherwise. Probes and API docs are mapped on the host, never on the group.
- **Rate limits**: `.RequireRateLimiting(ApiHardeningExtensions.AuthRateLimitPolicy)` only on endpoints that accept a **guessable** credential (login, register); token endpoints and everything else sit under the global per-client limiter. Probes are exempt (`.DisableRateLimiting()`), never short-circuited.
- **Host hardening lives in `AddApiHardening`/`UseApiHardening`** — forwarded headers (trust never widens: loopback-only unless `ForwardedHeaders:KnownProxies/KnownNetworks` say otherwise), security headers, `no-store` on every `/api/` response (an endpoint that wants caching sets its own `Cache-Control`, as the conditional `GetInvoice` does with `private, no-cache` on its 200 and 304 so a browser revalidates with the ETag; `/auth/` is always `no-store`), 1 MB body / 32 KB header caps. Don't re-add any of it per endpoint; raise the body limit only on the endpoint that needs it.
- **Write endpoints add `.RequireIdempotency()`** (ADR-0018 amendment): the key is scoped `(user, method, route, key)`; the reservation is tracked in the command's unit of work and commits with it, so a failed command leaves nothing behind and two concurrent firsts resolve at the primary key (`Idempotency.Duplicate`, 409, returned by `AppDbContext.CommitAsync`) or, when the loser fails on the winner's data first (a feature's uniqueness check, a unique index that fires before the key), at the store re-check: the filter asks the store again after any other 4xx and answers from the winner's reservation, never with the feature's 409. A completed request's status, body, content type and `Location` are stored (64 KB default; `RequireIdempotency(maxReplayBodyBytes:)` raises it only on the endpoint that needs it) and replayed to a retry with the same body as `Idempotency-Replayed: true`; a different body under the same key is a 422 `Idempotency.FingerprintMismatch`, a retry while the first request still runs a 409 `Idempotency.InFlight`. Anything an endpoint does after the handler returned success is post-commit work and uses `CancellationToken.None` — a fault there is a 500 whose retry is a 409, never a re-run. Write endpoints also **invalidate the read cache through the injected `CacheKeys` service** (ADR-0026) — never hand-build key strings; with multi-tenancy the key carries the tenant because a cache hit bypasses the EF tenant filter.
  - **The key itself**: one header value, at most 128 characters and not blank. A repeated header or a comma-separated list is 400 `Idempotency.InvalidKey`, never joined into one key the caller never sent. `RequireIdempotency(keyRequired: true)` makes the key mandatory (400 `Idempotency.KeyRequired` without one) on a create, whose accidental repeat would be a second resource (`CreateInvoice` is the model); the writes to an existing resource leave it optional, so a caller may opt out.
- **List endpoints** bind `page`/`pageSize` inline with `[Range(PagingLimits.MinPage, PagingLimits.MaxPage)]` / `[Range(PagingLimits.MinPageSize, PagingLimits.MaxPageSize)]` (camelCase names, bounds and defaults land in the document; the query's validator enforces the same bounds, 1..10000 and 1..100; the validator's literals are pinned by `EndpointContractTests.Every_paged_list_holds_its_documented_bounds_at_the_wire`, which reads every paged GET from the served document, so a new list needs no bounds test of its own; a GET whose 200 is a `PagedResponse<T>` without both in its query fails `The_lists_read_from_the_query_are_the_GETs_that_answer_a_paged_response`) and return the `PagedResponse<T>` envelope through the one shared mapping, `result.Value.ToPagedResponse(item => item.ToDto())` (`PagedResponseMappings` in Api.Common) — never a bare array, a per-feature copy of the mapping or a `new PagedResponse<T>(...)` (`ConventionTests.The_paged_envelope_is_built_only_by_the_shared_mapping`).
- **Concurrency**: the unit of work never throws for an expected outcome — `IUnitOfWork.CommitAsync` returns a stale `xmin` as `UnitOfWorkErrors.ConcurrencyConflict`, which reaches the endpoint as a failed `Result` (409 via `CustomResults`). Nothing in Presentation catches EF exceptions.
- OpenAPI metadata comes from `TypedResults` + `.WithTags`/`.WithSummary`/`.WithDescription` (`EndpointMetadataTests` insists on summary and description); the problem responses, `Location` and the conditional-GET members are added by shape (ADR-0025). A Result-produced status the shape cannot infer (an anonymous endpoint's 401/403/409, which has no security requirement and no route id) is declared with a bare `.Produces(StatusCodes.Status401Unauthorized)` — the transformer gives it the `ProblemResponse` body; never `ProducesProblem` or a typed `Produces<T>(4xx)`, and never one the shape already adds. A GET that honours `If-None-Match` declares `.SupportsConditionalGet()` and evaluates the header with `HttpRequest.IsNotModified(etag)` (parsed, weak comparison), never by string compare; a write that honours `If-Match` declares `.SupportsConditionalWrite()`, reads it with `HttpRequest.TryGetExpectedVersion(...)` into the command's `ExpectedVersion` (false → 412) and lets the handler compare. Under a GET that answers an `ETag`, every write does: `OpenApiDocumentTests.Every_write_to_a_resource_that_answers_an_ETag_takes_If_Match` fails on one that does not, unless `WritesWithoutIfMatch` names it with its reason. After any endpoint change regenerate `docs/api/openapi.v1.json` (`UPDATE_OPENAPI_SNAPSHOT=1 dotnet test tests/Trellis.ApiTests`); `OpenApiSnapshotTests` fails until you do. Scalar UI is dev-only, and so is the root redirect to it (`GET /` → `/scalar/v1`, `.ExcludeFromDescription()`, outside `/api/`).

`Api.Contracts` is a pure DTO surface — no references, no logic (ADR-0013).
