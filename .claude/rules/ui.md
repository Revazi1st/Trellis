# UI layer rules

`UI.Common` is the shared Razor Class Library for the Blazor web host. Keep it **render-mode-agnostic** — only `Microsoft.AspNetCore.Components.*` + `HttpClient`, no host-specific APIs — so it stays cleanly reusable (ADR-0015).

- **Talk to the API only through the typed clients** (`IInvoiceApiClient`, `IAuthApiClient`) over `Api.Contracts`; they return `ApiResult<T>` so components handle failures without exceptions. Every call goes through **`ApiCall`** (Services/): no response, a timeout (the clients' 15 s `HttpClient.Timeout`, or the host pipeline's), an open circuit (Polly's rejections, recognised by name — UI.Common has no Polly reference), unreadable JSON or a 2xx without its body all become the service-unavailable failure with no `StatusCode`; only the caller's own cancellation propagates, and a bug still throws. The typed client sends a **fresh `Idempotency-Key` per logical POST** — never POST with a raw `HttpClient`.
- **Failures are described in one place**: `ApiResponses` (Services/) turns a failed call into `ApiResult.Error`, keyed on the problem's `code`, falling back to status and `detail`. A 400/403/409 shows the server's `detail` (a 400 with validation errors shows those errors), a 429 a `Retry-After` hint, a 5xx or an unreachable API a service-unavailable sentence. Pages display `result.Error` and never write their own sentence for a 4xx; code that needs more branches on `result.Problem.Code` / `result.StatusCode` (`Problem` is `Api.Contracts.Common.ProblemResponse`, `Errors` its `{field, code, description}` list) and never parses `title`.
- **Forms**: an `EditForm` over a model in `Forms/` whose DataAnnotations **mirror the command validator** (change the validator, change its mirror), plus `<DataAnnotationsValidator />` and `<ServerValidation @ref="…" />`. On failure, `_error = _server.Show(result)`: each `errors[]` entry goes under the input whose property it names (a `ValidationMessageStore`, case-insensitive match), and the returned sentence — the whole-request errors (`field: null`), or "Some of the entered values are invalid." when every error found its input — goes in the form's single `role="alert"` paragraph. No `<ValidationSummary />` (it repeats every message). Inputs whose `min`/`step` shape the control sit in a `novalidate` form so the messages, not browser bubbles, explain.
- **Session lifetime** is handled for you: `TokenAuthenticationStateProvider` (also the `IAccessTokenSource`) rotates expired access tokens through `/auth/refresh` (single-flight, 30 s before expiry), and `BearerTokenHandler` attaches the currently-valid token to every request. Only a **401** from refresh ends the session; a 429, a 5xx or no response keeps the stored pair, holds off the next attempt for 5 s (`TimeProvider`, registered by `AddSharedUi` unless the host has one) and hands back the stored token, so a protected page does not bounce to sign-in (ADR-0021). **Sign-out** (`SignOutAsync`) forgets the pair, announces it, then revokes the refresh token (`POST /auth/logout`, best-effort); UI.Web's `RevokeSessionOnCircuitClose` revokes when a circuit closes. Components never touch tokens directly.
- **Protected pages** inherit `ProtectedPage` (component-level auth guard) and override `OnAuthorizedAsync`; one that overrides `OnParametersSetAsync` calls the base, which re-runs the guard whenever the auth state changes mid-page. An anonymous user goes to `login?returnUrl=<this page>` (`LoginRedirect`); the sign-in page returns only to a **plain relative path inside the app** (`LoginRedirect.LocalReturnUrl` — never redirect to a query-string value unchecked). Do **not** use endpoint `[Authorize]` — client-token Blazor Server has no server auth scheme to challenge (ADR-0007).
- **Permission-gated UI** uses `<AuthorizeView Roles="permission:name">` (the auth state provider maps permission claims to roles).
- **A page below a list opens with a way back to it**: a "Back to invoices" `NavLink` (`class="back"`) above the heading, rendered whatever the load state; the top bar is not the only way back. A list's filter belongs in the address (`invoices?status=Draft`, read with `[SupplyParameterFromQuery]`), so Back and a bookmark keep it, as links with the current one `aria-current`.
- **Success is a notification** (`INotificationService.Success("Invoice issued.")`, shown by the layout's `Notifications` live region for 8 s); failure stays next to what failed.
- **Accessibility**: a repeated link names its target (`aria-label="View the invoice for …"`); a loading placeholder is `role="status"`; landmarks are labelled (`<nav aria-label="Main">`); text on a coloured fill uses its `--on-*` token (≥ 4.5:1 in both colour schemes); one alert per failure.
- **Design system** (`docs/design-system.md`, ADR-0032): the values live in `wwwroot/tokens.css`, each colour once as `light-dark(#light, #dark)` in opaque hex, and `wwwroot/app.css` holds the components and writes no colour (a tint is `color-mix()` of two tokens; a variant aliases a token). A page carries the documented classes only: no `style=` attribute, no `<style>` block, no `.razor.css`. A new visual element is a component with its rule in `app.css` and its subsection in the doc's Components section; text sits on `--bg`/`--surface`/`--surface-2` or on a fill with that fill's `--on-*`; a new colour is a pair with its `--on-*`, and the contrast fact decides whether it may be text. `DesignSystemTests` (ArchitectureTests) holds all of it, both ways between the doc and the files.
- **Platform differences** go behind seams: `ITokenStore` (host-provided), API base address (host-provided), `UiOptions` (host-configured; `ShowDevelopmentHints` comes from the host's `IsDevelopment()` and gates the seeded-admin hint on `/login`). Never bake in a host-specific detail.
- **The host owns its shell**: UI.Web's `App.razor` picks the render mode per request (`AcceptsInteractiveRouting`) and carries the `blazor-error-ui` bar; `/Error` (`[ExcludeFromInteractiveRouting]`, `ErrorLayout` with no services) is the production exception page. `Program.cs` sends `Content-Security-Policy` (`script-src 'self'; object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'`), `X-Frame-Options: DENY`, `nosniff` and `Referrer-Policy: same-origin` on every response. Keep scripts in files (no inline `<script>`); `style-src` stays open because Blazor's reconnect overlay injects an inline `<style>`.
- **Tests** live in `tests/Trellis.ApiTests/Ui/` behind the `IncludeUI` guard (the csproj's XML-comment `IncludeUI` conditional, a C# `IncludeUI` conditional at the top of every file, and the folder is on template.json's `(!IncludeUI)` exclude list so `--include-ui false` output does not ship empty files): `UiHarness` runs the real `AddSharedUi` graph over a scripted `HttpMessageHandler` and a manual clock — no browser, no host; components render through the framework's `HtmlRenderer`; `WebHostTests` boots UI.Web itself (aliased `webhost`) in Production. The design system's facts are `tests/Trellis.ArchitectureTests/DesignSystemTests.cs` (the whole file behind the same `IncludeUI` conditional, and on the exclude list): a source scan over the `.razor` and `.css` files, `tokens.css` and `docs/design-system.md`, each fact with a positive control.
