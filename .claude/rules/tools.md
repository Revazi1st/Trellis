# Tools rules

## AppHost (`tools/Trellis.AppHost`)

- Aspire orchestration: postgres (image major pinned — data volumes don't survive major bumps; a persistent lifetime, so the container outlives the AppHost, which an Aspire test strips with the volume through `UseThrowawayDatabase`) → migrations (`WaitFor`) → api (`WaitForCompletion(migrations)`) → web; api and web are healthy once their own `/health` answers (`WithHttpHealthCheck`), not when their process starts. `aspire run` needs a real host, not the SDK container (ADR-0008).
- **Resource names come from `ServiceNames`** (`src/Shared/Trellis.ServiceDefaults/ServiceNames.cs`), which the AppHost references with `IsAspireProjectResource="false"`: a library it compiles against, not a project it runs. Code that names a resource uses the same constant (`GetConnectionString(ServiceNames.Database)`, a test host's `$"ConnectionStrings:{ServiceNames.Database}"`, `$"https+http://{ServiceNames.Api}"`, the E2E test's waits), so a rename is one edit; JSON, launch settings and YAML keep the literal. A new resource gets its constant first.
- `AddDockerComposeEnvironment("compose")` backs `aspire publish`; images come from `dotnet publish /t:PublishContainer` — no Dockerfiles. In publish mode only, the AppHost declares the two app secrets as parameters (`signing-key` → `Authentication__SigningKey` on api, `seed-admin-password` → `Seed__AdminPassword` on migrations; `SIGNING_KEY` and `SEED_ADMIN_PASSWORD` in `.env`) and gives the long-running services (postgres, api, web, and the cache with Redis) `restart: unless-stopped`; the dashboard's UI is published on the host's loopback only. The output has no TLS, health checks or resource limits: `docs/deployment.md` (the one-host quick start and the compose table) lists what to add, so keep it in step when the AppHost changes what it publishes.

## MigrationService (`tools/Trellis.MigrationService`)

- `MigrationWorker` applies EF migrations, seeds, then `StopApplication()` — the API waits on successful exit; a failure sets `ExitCode = 1` so the wait fails loudly.
- **Non-HTTP host**: registers `SystemCurrentUser` for `ICurrentUser` and (with multi-tenancy) `SystemTenantContext` for `ITenantContext` — every new host-scoped port needs a system stand-in here or `AppDbContext` won't resolve.
- **Seed guards**: sample data (demo invoices) seeds in Development only; the worker **refuses to seed `SeedOptions.DefaultAdminPassword` outside Development** — override via the `Seed` section in real environments. `SeedOptions` is validated at boot (`ValidateDataAnnotations().ValidateOnStart()`; a failure exits 1), and roles and the admin go through `IdentitySeed` (Persistence), which throws on any failed `IdentityResult` — so a rejected password exits 1 instead of logging success. The sample invoices' transitions are checked the same way (`Seeded`): a `Result` the domain refuses throws rather than saving a half-built sample.
- Permission seeding iterates `Roles.Permissions` (Application) — new permissions/roles flow through automatically; never hard-code them here.

## Analyzer (`tools/Trellis.Analyzers`)

- **RSLT001** (ADR-0030) fails the Release build on a statement that drops a SharedKernel `Result`, `Result<T>` or `Error`, the UI's `ApiResult<T>` or an `IdentityResult`, or a value carrying one (an array, a sequence, a tuple, a task: `await Task.WhenAll(...)`): a call, an awaited task, a conditional access, an object creation, `Wait()`, a void expression body, an unawaited task where CS4014 is silent, a collection initializer's `Add`; and on a computed `Task<Result>` converted to a plain `Task` (`public Task Handle(...) => port.PushAsync(...)`). Razor `@code` blocks are analysed; other generated code is not. `Directory.Build.props` loads it into every project under `src/`, `tests/` and `tools/` as an Analyzer item (never referenced, never copied), so a new project there gets it with no edit. Exempt: NSubstitute's `Received()` call checks, an assertion that hands back what it checked, the body of `Should.ThrowAsync(() => ...)`, a call that hands back a held result (`Tap` on a local, `Stack.Pop`, `Interlocked.Exchange`), expression trees. ADR-0030 lists the gaps.
- **A deliberate drop** is `_ = …` with a one-line reason. Never a `#pragma`, a `[SuppressMessage]` or a severity line in `.editorconfig` (`ResultDiscardAnalyzerTests` fails when `.editorconfig` lowers it).
- **Version ceiling**: `Microsoft.CodeAnalysis.CSharp` in `Directory.Packages.props` stays at or below the compiler of the SDK in `global.json` (an older compiler cannot load the analyzer: CS9057) and at or above what `Microsoft.EntityFrameworkCore.Design` requires (NU1109 otherwise). It moves by hand with an SDK bump (`docs/development.md`, *Bumping the SDK*); Dependabot proposes patches only.
- netstandard2.0 under `EnforceExtendedAnalyzerRules`: no file, network or clock access in the analyzer. A change lands with a fact in `ResultDiscardAnalyzerTests` for a shape it reports and one it leaves alone.

## CI supply-chain gates

- **Central package management** (ADR-0029): versions live only in `Directory.Packages.props` (transitive pinning on); a package family that shares version floors moves in one Dependabot group (`.github/dependabot.yml`) — add a new family to its group in the same change. A package numbered after .NET (10.x on .NET 10) also needs a semver-major ignore there unless an existing pattern covers it: its next major comes with the next .NET, a migration made by hand.
- **NuGetAudit** (`all` + `low`, `Directory.Build.props`) fails Release and CI builds on any advisory, transitive included (NU1901–NU1904). Playbook in `docs/development.md` ("Vulnerable packages"): upgrade, else pin the transitive in `Directory.Packages.props` with the advisory in a comment, else `NuGetAuditSuppress` one advisory with its reason. Never lower the level or the mode to get a build through.

## Template source only (this section never ships)

`TemplateSource` is a constant that is false whenever `dotnet new` runs, so the engine drops this section from every generated project, which keeps no template directives.

- **Template toggles are `#if` blocks** (`UseRedis`, `IncludeUI`) processed at `dotnet new` time. The csproj defines `IncludeUI` in `DefineConstants` (inside an XML-comment `#if` directive on `IncludeUI`) so the template *source* compiles too — keep both sides in sync when adding a toggle (`add-toggle` skill).
- **YAML has no preprocessor.** `dotnet new` reads hash-comment directives in workflows, `docker-compose.yml` and `dependabot.yml`; in this repository every one of them is an ordinary comment.
  - **A plain `#if (X)` … `#else` … `#endif` block is live in BOTH branches here**: CI runs every line of each. Use it only when that is harmless (the `ui-tests` job in `ci.yml`, which ships only with `--include-ui-tests`).
  - **A branch that must stay inert here uses the doubled-hash form** `##if (X)` / `##else` / `##endif`: every line of the inert branch commented with one `#` in column 0, every other hash in the block doubled. The engine strips each single hash in the branch it keeps and turns `##` into `#`, so the commented lines come alive in generated output. Nothing nests inside such a block. Worked example: the Redis steps in `ci.yml`.
  - **`#if (TemplateSource)` marks source-only lines**: the block runs here and never ships (the `ci.yml` step that runs `scripts/check-template-toggles.sh`; this section, in the XML-comment form).
- **Generated output belongs to the consumer.** `template.json` excludes the template's own README, CHANGELOG, governance files and release runbook (keep the pack csproj's exclude list in step), and its second source, `.template.config/consumer/`, supplies the README stub, an empty CHANGELOG and the `.trellis-template.json` marker (template version, name, options). `LICENSE` is copy-only. Template CI's leftovers step fails on any generated line naming the template or its maintainer except the LICENSE copyright line and the marker; a shipped doc that must name the marker writes it with an escaped hyphen, `.trellis\-template.json`, which the `templateMarkerFile` symbol turns back into the name.
- **A directive stands alone on its line**: nothing but whitespace before it or after it (after its `-->` in the XML-comment form), condition in parentheses, symbol declared in `template.json`. The engine matches the token anywhere in a line and truncates the shipped file from there, so never quote one inside a `run:` script or a YAML comment, and it drops the whole line a directive is on, so text beside one is lost from generated output (the site, which reads `docs/`, would show it on every page). The same holds for the XML-comment form in shipped `.md` (the hash right after the comment's opening, no space between) and for `#if` in `.sh`. `scripts/check-template-toggles.sh` enforces all of this; files `template.json` excludes outright (`template-ci.yml`, `release.yml`) are never processed and not checked.
- **`eng/readme/`** (the README's generated pictures and `render-diagrams.py`) is maintainer-only too: both exclude lists and Template CI's must-not-ship loop name it, and the "README pictures are current" step in `ci.yml` fails when the pictures go stale (`python3 eng/readme/render-diagrams.py` re-renders; `eng/readme/README.md` says when).
- **The documentation site is maintainer-only** (ADR-0031): `site/` (Astro + Starlight, with its own Node toolchain), the `site.yml` workflow that builds and deploys it, and ADR-0031 itself, whose `docs/INDEX.md` line sits in a `TemplateSource` block (so does ADR-0014's amendment that points at it). Both exclude lists and Template CI's must-not-ship loop name them, and `scripts/check-adr-links.sh` prunes `site/`. The site renders `docs/` in place, so a doc stays plain GitHub Markdown: it never links into `site/` or `eng/readme/`, and its directives stay alone on their lines (`site/README.md` says what the build does to a doc).
