# Tools rules

## AppHost (`tools/Trellis.AppHost`)

- Aspire orchestration: postgres (image major pinned — data volumes don't survive major bumps; a persistent lifetime, so the container outlives the AppHost, which an Aspire test strips with the volume through `UseThrowawayDatabase`) → migrations (`WaitFor`) → api (`WaitForCompletion(migrations)`) → web; api and web are healthy once their own `/health` answers (`WithHttpHealthCheck`), not when their process starts. With `UseRedis`, the `cache` is Valkey (`AddValkey`, major pinned like postgres's), which the API reaches through its Redis client: the Redis server and RedisInsight are not free for a product to ship, so neither is declared. In run mode only, `mailpit` (`AddMailPit`, CommunityToolkit.Aspire.Hosting.MailPit, image `axllent/mailpit`, MIT) catches the API's e-mail: the run-mode block sets the API's `Email__Provider=Smtp`, `Email__Smtp__Host`/`__Port` from the resource's SMTP endpoint, `__UseStartTls=false` and a `__FromAddress`, with no credentials (`SmtpOptionsValidator` refuses credentials in clear), and its HTTP endpoint is the dashboard's **Inbox** link; nothing waits for it (the outbox retries a receipt sent too early), and publish mode declares no catcher. `AppHostMailTests` (ApiTests) reads both from the app model. `aspire run` needs a real host, not the SDK container (ADR-0008), and so do the tests that start this AppHost through `Aspire.Hosting.Testing`: the Aspire end-to-end test and, where the solution has them, the browser tests, each after `UseThrowawayDatabase`. That step strips postgres and refuses an app model in which any other resource keeps a volume, a writable bind mount or a persistent lifetime: a resource you give one here must be stripped there too (`ThrowawayDatabaseTests` fails until it is).
- **Every container image is on an allowlist with its license** (ADR-0011, amendment of 2026-11-08): `ContainerImageTests.Every_container_image_the_AppHost_declares_is_on_the_allowlist` reads the AppHost for the default image of each `Add<Resource>(` (`AddPostgres` → `postgres`, `AddValkey` → `valkey/valkey`, `AddMailPit` → `axllent/mailpit`, `AddDockerComposeEnvironment` → the dashboard; one it cannot map fails), the tool tiles (`WithPgAdmin` → `dpage/pgadmin4`, `WithRedisInsight` → `redis/redisinsight`), `AddContainer` and `WithImage` literals (an image computed at run time fails), plus every `image:`, `container:` and `docker://` in the workflows and the root `docker-compose.yml`, comments included (an inert template branch is one), and fails on an image `ImageAllowlist` does not name. A new image is a license decision: read its license, then add the row with the license and where it is used; a new resource gets its default image in `ResourceImages`, a new tile method its row in `TileImages`. Control `The_image_scan_flags_an_image_off_the_allowlist` (`AddRedis(`, `WithRedisInsight(`, `AddContainer("grafana", "grafana/grafana")`).
- **Resource names come from `ServiceNames`** (`src/Shared/Trellis.ServiceDefaults/ServiceNames.cs`), which the AppHost references with `IsAspireProjectResource="false"`: a library it compiles against, not a project it runs. Code that names a resource uses the same constant (`GetConnectionString(ServiceNames.Database)`, a test host's `$"ConnectionStrings:{ServiceNames.Database}"`, `$"https+http://{ServiceNames.Api}"`, the E2E test's waits), so a rename is one edit; JSON, launch settings and YAML keep the literal. A new resource gets its constant first.
- `AddDockerComposeEnvironment("compose")` backs `aspire publish`; images come from `dotnet publish /t:PublishContainer` — no Dockerfiles. In publish mode only, the AppHost declares the two app secrets as parameters (`signing-key` → `Authentication__SigningKey` on api, `seed-admin-password` → `Seed__AdminPassword` on migrations; `SIGNING_KEY` and `SEED_ADMIN_PASSWORD` in `.env`) and gives the long-running services (postgres, api, web, and the Valkey cache with `UseRedis`) `restart: unless-stopped`; the dashboard's UI is published on the host's loopback only. The output has no TLS, health checks or resource limits: `docs/deployment.md` (the one-host quick start and the compose table) lists what to add, so keep it in step when the AppHost changes what it publishes.

## MigrationService (`tools/Trellis.MigrationService`)

- `MigrationWorker` applies EF migrations, seeds, then `StopApplication()` — the API waits on successful exit; a failure sets `ExitCode = 1` so the wait fails loudly.
- **Non-HTTP host**: registers `SystemCurrentUser` for `ICurrentUser` and (with multi-tenancy) `SystemTenantContext` for `ITenantContext` — every new host-scoped port needs a system stand-in here or `AppDbContext` won't resolve.
- **Seed guards**: sample data (demo invoices) seeds in Development only; the worker **refuses to seed `SeedOptions.DefaultAdminPassword` outside Development** — override via the `Seed` section in real environments. `SeedOptions` is validated at boot (`ValidateDataAnnotations().ValidateOnStart()`; a failure exits 1), and roles and the admin go through `IdentitySeed` (Persistence), which throws on any failed `IdentityResult` — so a rejected password exits 1 instead of logging success. The sample invoices' transitions are checked the same way (`Seeded`): a `Result` the domain refuses throws rather than saving a half-built sample.
- Permission seeding iterates `Roles.Permissions` (Application) — new permissions/roles flow through automatically; never hard-code them here.

## Analyzer (`tools/Trellis.Analyzers`)

- **RSLT001** (ADR-0030) fails the Release build on a statement that drops a SharedKernel `Result`, `Result<T>` or `Error`, the UI's `ApiResult<T>` or an `IdentityResult`, or a value carrying one (an array, a sequence, a tuple, a task: `await Task.WhenAll(...)`): a call, an awaited task, a conditional access, an object creation, `Wait()`, a void expression body, an unawaited task where CS4014 is silent, a collection initializer's `Add`; and on a computed `Task<Result>` converted to a plain `Task` (`public Task Handle(...) => port.PushAsync(...)`). Razor `@code` blocks are analysed; other generated code is not. `Directory.Build.props` loads it into every project under `src/`, `tests/` and `tools/` as an Analyzer item (never referenced, never copied), so a new project there gets it with no edit. Exempt: NSubstitute's `Received()` call checks, an assertion that hands back what it checked, the body of `Should.ThrowAsync(() => ...)`, a call that hands back a held result (`Tap` on a local, `Stack.Pop`, `Interlocked.Exchange`), expression trees. ADR-0030 lists the gaps.
- **A deliberate drop** is `_ = …` with a one-line reason. Never a `#pragma warning disable` (naming RSLT001, or bare), a `[SuppressMessage]`, a `<NoWarn>` or `<WarningsNotAsErrors>` entry, `RunAnalyzers`, `RunAnalyzersDuringBuild` or `TreatWarningsAsErrors` set to false in a project (in any configuration), or a severity below warning in an `.editorconfig` or `.globalconfig`, on RSLT001's own line or a bulk one (`dotnet_analyzer_diagnostic.severity`, or its `category-Reliability` form): `ResultDiscardAnalyzerTests.Nothing_in_the_repository_silences_RSLT001` scans `src/`, `tools/`, `tests/` and the root's MSBuild and configuration files for all of them (the analyzer's own project and that test file aside). The root `.editorconfig` names `dotnet_diagnostic.RSLT001.severity = warning`, which outranks every bulk line, its generated-code section's included (generated files are exempt as generated code), and the Release-build control fails when it lowers the rule. A text scan cannot see a switch on the command line or in a `Directory.Build.rsp`, nor a `[SuppressMessage]` that names the id through a constant.
- **Version ceiling**: `Microsoft.CodeAnalysis.CSharp` in `Directory.Packages.props` stays at or below the compiler of the SDK in `global.json` (an older compiler cannot load the analyzer: CS9057) and at or above what `Microsoft.EntityFrameworkCore.Design` requires (NU1109 otherwise). It moves by hand with an SDK bump (`docs/development.md`, *Bumping the SDK*); Dependabot proposes patches only.
- netstandard2.0 under `EnforceExtendedAnalyzerRules`: no file, network or clock access in the analyzer. A change lands with a fact in `ResultDiscardAnalyzerTests` for a shape it reports and one it leaves alone.

## CI supply-chain gates

- **Central package management** (ADR-0029): versions live only in `Directory.Packages.props` (transitive pinning on); a package family that shares version floors moves in one Dependabot group (`.github/dependabot.yml`) — add a new family to its group in the same change. A package numbered after .NET (10.x on .NET 10) also needs a semver-major ignore there unless an existing pattern covers it: its next major comes with the next .NET, a migration made by hand.
- **NuGetAudit** (`all` + `low`, `Directory.Build.props`) fails Release and CI builds on any advisory, transitive included (NU1901–NU1904). Playbook in `docs/development.md` ("Vulnerable packages"): upgrade, else pin the transitive in `Directory.Packages.props` with the advisory in a comment, else `NuGetAuditSuppress` one advisory with its reason. Never raise the level or narrow the mode to get a build through.
- **Step by step**: adding a package, answering an advisory and bumping the SDK are in `.claude/rules/dependencies.md`, which loads with `Directory.Packages.props`, `Directory.Build.props`, `global.json`, `.github/dependabot.yml`, the SDK image and the tool manifest.

## Template source only (this section never ships)

`TemplateSource` is a constant that is false whenever `dotnet new` runs, so the engine drops this section from every generated project, which keeps no template directives.

- **Template toggles are `#if` blocks** (`UseRedis`, `IncludeUI`) processed at `dotnet new` time. The csproj defines `IncludeUI` in `DefineConstants` (inside an XML-comment `#if` directive on `IncludeUI`) so the template *source* compiles too — keep both sides in sync when adding a toggle (`add-toggle` skill).
- **YAML and `.editorconfig` have no preprocessor.** `dotnet new` reads hash-comment directives in workflows, `docker-compose.yml`, `dependabot.yml`, `.editorconfig`, `.gitignore`, `.gitattributes`, `.dockerignore` and `Dockerfile` (the engine in SDK 10.0.403 lists them as one group of hash-comment files, and Template CI's generated Format check proves the `.editorconfig` block on every leg); in this repository every one of them is an ordinary comment.
  - **A plain `#if (X)` … `#else` … `#endif` block is live in BOTH branches here**: CI runs every line of each. Use it only when that is harmless (the `ui-tests` job in `ci.yml`, which ships only with `--include-ui-tests`).
  - **A branch that must stay inert here uses the doubled-hash form** `##if (X)` / `##else` / `##endif`: every line of the inert branch commented with one `#` in column 0, every other hash in the block doubled. The engine strips each single hash in the branch it keeps and turns `##` into `#`, so the commented lines come alive in generated output. Nothing nests inside such a block. Worked example: the Redis steps in `ci.yml`.
  - **`#if (TemplateSource)` marks source-only lines**: the block runs here and never ships (the `ci.yml` step that runs `scripts/check-template-toggles.sh`; this section, in the XML-comment form). `.editorconfig`'s `dotnet_sort_system_directives_first` sits in one: it keeps `dotnet format`'s using-order check (IMPORTS) on for this repository, whose files are sorted under the template's name, and leaves it out of every generated project, whose own namespaces sort elsewhere, until the project opts in as the comment there says.
- **Generated output belongs to the consumer.** `template.json` excludes the template's own README, CHANGELOG, governance files and release runbook (keep the pack csproj's exclude list in step), and its second source, `.template.config/consumer/`, supplies the README stub, an empty CHANGELOG and the `.trellis-template.json` marker (template version, name, options). `LICENSE` is copy-only. Template CI's leftovers step fails on any generated line naming the template or its maintainer except the LICENSE copyright line and the marker; a shipped doc that must name the marker writes it with an escaped hyphen, `.trellis\-template.json`, which the `templateMarkerFile` symbol turns back into the name.
- **Template CI's content gate is `scripts/check-generated-content.sh`, and the local legs run it too.** It reads a generated project for a file or folder named after the template, an unprocessed directive, a `TRELLIS_` token, a sentence that reads "a Acme.Shop …" after the rename, a maintainer-only script (`check-template-toggles.sh`, `test-template.sh`, `check-readme-sync.sh`, `regenerate-initial-migrations.sh`, itself) named in any shipped file, a `[Migration]` id that is not its file's name, anything but one initial migration with tenant columns exactly when the leg asks for multi-tenancy, and the files that never ship; its header lists the checks. A shipped file names a maintainer-only script only inside a `TemplateSource` block: a test's comment that named `test-template.sh` failed every leg once. Template CI's instantiate job runs it right after `dotnet new`, `scripts/test-template.sh` at the same point of every leg (its CONTENT column), and `ci.yml` its `--self-test`, which plants each defect in a throwaway tree; a new check gets a case there. The script is maintainer-only: both exclude lists and the must-not-ship loop name it, and a new maintainer-only script joins all three and the gate's search. What only Template CI runs: the leftovers step (a line naming the template or its maintainer, the consumer files, the must-not-ship loop), the generated project's own link, hook and doctor checks, actionlint over its workflows, the Windows job and the pack job.
- **A port symbol's literal is replaced wherever it appears**: the `port` generators in `template.json` (`15171`, `17171`, `19171`, `20171`, `21171`, `22171`, the AppHost's launch-profile ports) replace their literal in every file the engine processes, not only `launchSettings.json`. A migration id is a timestamp and can contain one by chance (`20261111171711` holds `17171`): the generated project then carries a `[Migration]` attribute rewritten to a port number under a file still named after the real id, and its own `migrations remove` finds no file. `MigrationSnapshotTests` refuses such an id in either set, `scripts/regenerate-initial-migrations.sh` generates again a minute later until the id holds none (a literal sits in an id for ten minutes at most), and Template CI's content gate compares every generated migration's attribute with its file name.
- **A directive stands alone on its line**: nothing but whitespace before it or after it (after its `-->` in the XML-comment form), condition in parentheses, symbol declared in `template.json`. The engine matches the token anywhere in a line and truncates the shipped file from there, so never quote one inside a `run:` script or a YAML comment, and it drops the whole line a directive is on, so text beside one is lost from generated output (the site, which reads `docs/`, would show it on every page). The same holds for the XML-comment form in shipped `.md` (the hash right after the comment's opening, no space between) and for `#if` in `.sh` and `.editorconfig`. `scripts/check-template-toggles.sh` enforces all of this (in `.md` and `.sh` the directive's shape alone, not its symbol or its balance); files `template.json` excludes outright (`template-ci.yml`, `release.yml`) are never processed and not checked.
- **`eng/readme/`** (the README's generated pictures and `render-diagrams.py`) is maintainer-only too: both exclude lists and Template CI's must-not-ship loop name it, and the "README pictures are current" step in `ci.yml` fails when the pictures go stale (`python3 eng/readme/render-diagrams.py` re-renders; `eng/readme/README.md` says when).
- **A fact the README or the site states has one home, and `scripts/check-readme-sync.sh` holds the copies its header lists to it** (ADR-0031, amendment of 2026-11-15): the pitch in `eng/readme/pitch.md` (one line, one `*…*` span, read by `render-diagrams.py` and the site, copied into both READMEs, the pack csproj and `template.json`), the options and their descriptions, the quickstart commands of `site/src/data/repo.mjs`, the use cases and their permissions, the seeded login (a new copy joins the script's `login_copies` list), the gate numbers, the prerequisites, the ports, the agent toolkit, the links and their anchors, the option bullets of `docs/overview.md`, and the screenshots in `eng/readme/shots/` with their alt texts and caption, copied by hand from CI's `ui-screenshots` artifact (`eng/readme/README.md`, *Screenshots*, says when and how). The script is maintainer-only: both exclude lists and Template CI's content gate and must-not-ship loop name it, and `ci.yml` runs it after its `--self-test` in the template-source block. A message names the copy to update; when it says "teach scripts/check-readme-sync.sh", a format changed and the script learns the new one.
- **The template ships two initial migrations, both written by the pinned EF Core**: the default set in `src/Infrastructure/Trellis.Persistence/Migrations/`, and the multi-tenant model's in `.template.config/tenancy/Migrations/`, outside every project (inside the Persistence project `migrations add` would write to whichever `AppDbContextModelSnapshot.cs` it finds). `template.json` gives a project one of them: a source conditional on `UseMultitenancy` lays the second over the first one's folder and a modifier under the same condition keeps the first out. The engine renames that source's `target` with the project name as typed, while every other path gets the identifier-safe form (`projectPathName`), so for a name that needs that form (`acme-shop`, which `dotnet new` warns will not build and should be re-created) the set lands in `acme-shop.Persistence/Migrations/`, beside the `acme_shop.Persistence` project. Without the modifier `dotnet new` succeeds and ships both; a source folder that is missing or empty makes the whole template invalid (MV012). **A model change or an EF Core bump regenerates both in one run**: `scripts/regenerate-initial-migrations.sh`, which generates each set in a project created from the working tree under the template's own name and replaces the files only when both can ship; never one set with `scripts/ef.sh`. Its `--check` mode writes nothing and fails unless every committed file is what the script generates, the id aside; Template CI's pack job runs it. Never `migrations remove` on a host: with `--force` it reverts the migration on whatever database `localhost` is. `MigrationSnapshotTests` (ArchitectureTests) holds both sets: the pinned `ProductVersion`, no port literal in an id, the same migrations in the Persistence namespace, the second snapshot equal to the first once the tenant seam is taken out, and the wiring. Template CI counts what shipped on every leg and runs the first-migration command and `MigrationDriftTests` on the multi-tenancy legs. The script and the test are maintainer-only: both exclude lists and Template CI's must-not-ship loop name them, and its content gate searches every generated file for the script's name. An option that changes the model ships a set of its own the same way, and its target is renamed the same way (the `add-toggle` skill, step 6a).
- **The documentation site is maintainer-only** (ADR-0031): `site/` (Astro + Starlight, with its own Node toolchain), the `site.yml` workflow that builds and deploys it, and ADR-0031 itself, whose `docs/INDEX.md` line sits in a `TemplateSource` block (so does ADR-0014's amendment that points at it). Both exclude lists and Template CI's must-not-ship loop name them, and `scripts/check-adr-links.sh` leaves `./site` out of both its checks in a `#if (TemplateSource)` block (the engine processes `#if` in `.sh` too), so a generated project checks a `site/` folder of its own. The site renders `docs/` in place, so a doc stays plain GitHub Markdown: it never links into `site/` or `eng/readme/`, and its directives stay alone on their lines (`site/README.md` says what the build does to a doc).
