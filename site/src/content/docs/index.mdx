<p class="label">What you get</p>

## Opinionated where it pays, open where it should be

<p class="sub">Every card opens the page that explains the piece, rendered from the repository's own <code>docs/</code>.</p>

<div class="bento">

<Card title="A pipeline, no mediator" icon="list-format">

Commands and queries run through decorators: tracing, logging, validation, unit of work. Failures travel as a `Result` and reach the client as RFC 9457 problem details. A discarded `Result` fails the build. Paying an invoice is this whole handler:

<Excerpt path="src/Core/Trellis.Application/Features/Invoices/PayInvoice/PayInvoiceCommandHandler.cs" from="internal sealed class PayInvoiceCommandHandler" wrap />

[See the architecture →](/understand/architecture/)

</Card>

<Card title="A rich domain, worked end to end" icon="document">

Aggregates created through `Create(...)` that returns a `Result`, value objects as sealed records mapped as EF complex types, hand-rolled strongly typed ids. The Invoices slice is the reference: create, issue, pay, void, list, with a receipt e-mail after the commit.

<Excerpt path="src/Core/Trellis.Domain/Invoices/Invoice.cs" from="public Result MarkPaid(" wrap />

[Read the reference feature →](/features/invoices/)

</Card>

<Card title="Outbox and idempotency" icon="random">

Domain events are written in the same transaction and dispatched after it, at least once, with per-handler checkpoints. Idempotency keys and strong ETags on the API.

[The outbox decision →](/decisions/0018-transactional-outbox-and-idempotency/)

</Card>

<Card title="Tests that hold the shape" icon="approve-check">

Architecture tests pin the layer rules, integration tests run on a real PostgreSQL in Testcontainers, API tests go through the real pipeline, and a Playwright suite is one toggle away.

[The testing page →](/develop/testing/)

</Card>

<Card title="Built for agents too" icon="comment-alt">

`AGENTS.md`, path-scoped rules, skills for adding a feature or an integration, and a docs-drift gate in CI, so a person and an AI assistant read the same instructions.

[Read the agent instructions →](https://github.com/Revazi1st/Trellis/blob/main/AGENTS.md)

</Card>

</div>

## Up and running in three steps

<p class="sub">Forward slashes throughout; every command runs the same in bash, zsh and PowerShell.</p>

<Steps>

1. **Install the template**

   Needs the .NET 10 SDK ({sdkVersion} or later). Nothing else yet.

   <Tabs syncKey="install-source">
     <TabItem label="nuget.org">
       <Code code={quickstart.install} lang="bash" frame="terminal" />
     </TabItem>
     <TabItem label="From a clone of main">
       <Code code={quickstart.fromClone.slice(0, 2).join('\n')} lang="bash" frame="terminal" />
     </TabItem>
   </Tabs>

2. **Create a solution**

   Name it the way you would name the root namespace. Add toggles as you need them.

   <Code code={[quickstart.create, quickstart.createWithToggles].join('\n')} lang="bash" frame="terminal" />

3. **Run it**

   Needs Docker running. The AppHost starts PostgreSQL, applies the migrations, seeds the first administrator and opens the Aspire dashboard.

   <Code code={quickstart.run.join('\n')} lang="bash" frame="terminal" />

   Sign in with the seeded administrator named in the generated README, or walk the thirteen requests of `Trellis.Api.http` from the [Try it](/features/invoices/#try-it) section.

</Steps>
