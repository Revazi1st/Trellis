## Prerequisites

Each tool says when you need it; only the SDK is needed to create a solution.

| Tool | Needed for | Check it |
|---|---|---|
| .NET 10 SDK, {sdkVersion} or later | installing the template, creating, building and running the solution | `dotnet --version` |
| Docker (Docker Desktop or Linux Docker Engine) | PostgreSQL, the integration tests (Testcontainers), the SDK container | `docker version` |
| Aspire CLI 13.5 or later, optional | `aspire run`; `dotnet run --project tools/<Name>.AppHost` starts the same app | `aspire --version` |
| PowerShell, optional | installing the browsers for the optional Playwright tests | `pwsh --version` |

OrbStack, Colima and Podman work too: see [Docker engines other than Docker Desktop](/develop/development/#docker-engines-other-than-docker-desktop).

## Create a solution

<Code code={quickstart.create} lang="bash" />

Name the project with dot-separated parts made of letters and digits, each starting with a letter (`Acme.Shop`): hyphens, spaces and underscores turn into underscores in namespaces, which analyzer rule CA1707 rejects. In the paths the docs show, `Trellis` reads as your project's name: `tools/Trellis.AppHost` becomes `tools/Acme.Shop.AppHost`.

## Options

Add options as flags, such as `--use-redis` or `--include-ui false` for an API-only solution. [Options](/start/options/) lists every one, with what it adds and what to do after creating the solution: with `--use-multitenancy`, for example, regenerate the initial migration before the first run.
